Real data is messy. Sellers leave boxes blank, a sensor goes offline, prices arrive as the text `"450,000"`, and the same row gets entered twice. Some of these make your code crash, which is annoying but honest. The others give you a believable wrong answer, which is worse. This lesson is the ten-minute check-and-fix routine that comes before any model sees the data.

## Finding the holes

<Analogy>
Before working out the class attendance rate, a teacher scans the register for blank boxes. Three blanks scattered across the term are a small fix. A column that is blank for most of the class (say, a CCA that only two students joined) is a different decision altogether. You look at the pattern of blanks first, and only then decide what to do.
</Analogy>

pandas marks a missing number as <Term def="Not a Number: a special floating-point value that pandas and NumPy use to mean 'missing'. Any arithmetic with NaN gives NaN.">NaN</Term> ("Not a Number"). Missing text may show up as `None` or `NaN`, and a missing date as `NaT` ("Not a Time"). pandas treats all of them as missing.

To find them, `df.isna()` gives a table the same shape as `df`, with `True` wherever a value is missing. Python counts `True` as 1 and `False` as 0, so:

- `df.isna().sum()` adds down each column: the **number** of missing values per column.
- `df.isna().mean()` averages down each column: the **fraction** missing (number missing ÷ number of rows).
- `df.isna().sum().sum()` adds those up again: the total for the whole table.

`df.isnull()` is exactly the same method as `df.isna()` (and `notnull()` is the same as `notna()`). Exam questions and tutorials use both spellings, so recognise `df.isnull().sum()` on sight.

`df.info()` from the last lesson shows the same thing from the other side, as non-null counts.

<MissingMap />

Why bother? Because missing values spread quietly:

```python
import numpy as np
import pandas as pd

s = pd.Series([30.0, np.nan, 31.0])
print(s + 1)                 # arithmetic with NaN gives NaN
print(s.mean())              # pandas skips NaN when it averages
print(np.mean(s.to_numpy())) # NumPy does not
print(np.nan == np.nan)      # NaN is not even equal to itself
```

pandas' `mean()` and `sum()` skip NaN by default, so your summary looks fine while the gaps are still there. NumPy returns `nan` instead, and scikit-learn models such as `LinearRegression` refuse to train at all: `fit` stops with `ValueError: Input X contains NaN.` You have to deal with the gaps yourself.

<Mistake>
Testing for missing values with `df['area'] == np.nan`. Because NaN is not equal to anything, not even another NaN, this is False for every row and finds nothing. Use `df['area'].isna()`.
</Mistake>

## Three ways to fix a gap: drop, fill or estimate

<Analogy>
A student missed one homework. To work out the class average you could leave that student out (drop), give them the class median mark (fill), or estimate their mark from the homeworks just before and after (interpolate). Each is a reasonable choice in some situations and a bad one in others.
</Analogy>

Two pieces of jargon you will meet in exam questions: keeping only the rows with no gaps at all is called <Term def="Analysing only the rows (samples) that have no missing values at all; every incomplete row is thrown away. In pandas: df.dropna().">complete-case analysis</Term>, and filling a gap with an estimated value (a median, the previous reading, a value on a line) is called <Term def="Replacing missing values with estimated ones, such as the column mean or median, the previous value, or an interpolated value.">imputation</Term>.

**Drop**: keep only real data, and lose some of it.

- `df.dropna()` removes every **row** that has any NaN. Good when there are few gaps and plenty of rows.
- `df.dropna(subset=['temp'])` removes only the rows where `temp` is missing and ignores gaps elsewhere. Good when only some columns matter.
- `df.drop(columns=['uv'])` removes the columns you name. Good for a column that is mostly empty.
- `df.dropna(axis=1)` removes every **column** that has even one NaN. Rarely what you want: a column with a single gap goes too.

**Fill**: keep the shape, and invent the missing values.

- `df.fillna(0)` puts a constant in every gap. Only when the constant truly means something (0 mm of rain).
- `df['c'].fillna(df['c'].median())` puts that column's median in its gaps. Good for numbers in no particular order.

**Estimate from the neighbours**: for rows in time order.

- `df.ffill()` copies the last known value forward. Good for time series that change slowly.
- `df.interpolate()` draws a straight line between the neighbours. Good for smooth time series.

Each of these returns a **new** DataFrame and leaves `df` unchanged, so remember to keep the result: `df = df.dropna()`. Many methods also accept `inplace=True`: `df.dropna(inplace=True)` changes `df` itself and returns `None`, so it does the same job. Never combine the two, because `df = df.dropna(inplace=True)` sets `df` to `None`.

When the data will train a model, work out the median (or any other fill value) from the **training** rows only, and reuse that same number for the test rows. The [leakage lesson](#/learn/data-and-features/splitting-and-leakage) explains why.

Try them all on a week of readings from a weather station. Watch two things: how the **shape** changes and how the **means** move.

<NaNFixer />

Dropping loses real data; filling invents data. You can see which one a method did from the shape alone: if the shape shrinks, data was lost; if it stays the same, gaps were filled with made-up values.

<KeyIdea>

Count the gaps first with `df.isna().sum()`, then choose. Drop rows when the gaps are few, drop a column that is mostly empty, fill unordered numbers with the median, and use `ffill` or `interpolate` for time series. Dropping shrinks the shape; filling keeps it but invents values.

</KeyIdea>

### How interpolate fills a gap

For a gap at row $t$ with known values $y_0$ at row $t_0$ before it and $y_1$ at row $t_1$ after it, linear interpolation uses

$$
y = y_0 + (y_1 - y_0)\,\frac{t - t_0}{t_1 - t_0}
$$

In words: start from the value before the gap, $y_0$; the whole change across the gap is $y_1 - y_0$; and $\frac{t - t_0}{t_1 - t_0}$ is the fraction of the way through the gap that row $t$ sits. With one gap between two equally spaced neighbours, that fraction is $\frac{1}{2}$, so the gap gets the average of its two neighbours.

<Steps title="Interpolating Thursday to Sunday by hand">
  <Step title="Find the known neighbours">
    Thursday (row 3) is 32.0 °C and Sunday (row 6) is 30.5 °C. Friday (row 4) and Saturday (row 5) are missing.
  </Step>
  <Step title="Work out the step per row">
    The total change is $30.5 - 32.0 = -1.5$ over $6 - 3 = 3$ rows, so each row changes by $-1.5 / 3 = -0.5$.
  </Step>
  <Step title="Walk along the line">
    Friday $= 32.0 - 0.5 = 31.5$ and Saturday $= 32.0 - 2 \times 0.5 = 31.0$. Check with the formula: for Saturday, $32.0 + (-1.5) \times \frac{5 - 3}{6 - 3} = 32.0 - 1.0 = 31.0$.
  </Step>
  <Step title="Compare with ffill">
    `ffill()` would copy 32.0 into both days instead, making Friday and Saturday hotter than either real neighbour.
  </Step>
</Steps>

### When not to fill at all

Some models can cope with gaps on their own: some <Term def="Models that make predictions by asking a series of yes/no questions about the features, such as 'is the area above 90?'. You meet them in module 17.">tree models</Term> can learn which way to send a missing value. Models that measure distances between rows or multiply the numbers by weights, such as k-nearest neighbours and linear regression, need every value, so for them you must drop or fill first.

Dropping rows also gets expensive fast when gaps are scattered. If each value is missing independently with probability 0.15, a row with 20 features is complete only when all 20 are present: probability $0.85^{20} \approx 0.04$. `dropna()` would throw away about 96% of the data.

<ExamTip>
For a "what is the shape after `dropna()`?" question, go row by row and keep only the rows with **no** NaN at all; the number of columns does not change. For `dropna(axis=1)` it is the other way round: keep only columns with no NaN, and the number of rows does not change. `fillna`, `ffill` and `interpolate` never change the shape. And `ffill` and `interpolate` cannot fill a gap in the **first** row, because nothing comes before it, so that NaN survives.
</ExamTip>

## Wrong types and duplicate rows

<Analogy>
At stocktake you check two things: that every price tag shows a number rather than a smudge, and that no item has been counted twice. A data table needs exactly the same checks.
</Analogy>

When pandas reads a CSV file, it gives each column one dtype. If even a single entry in a column of numbers is not a clean number, such as `"585,000"` (commas) or `"unknown"`, the whole column is stored as text, dtype `object` (pandas 3 shows `str`). Nothing crashes yet, but text behaves differently from numbers:

- Text is compared letter by letter, so `"720,000"` counts as larger than `"1,050,000"` (because "7" comes after "1").
- Text cannot be averaged: `mean()` raises a `TypeError`.

Fix types with:

- `df['price'].str.replace(',', '').astype(int)`: remove the commas, then convert. `astype` raises an error if any entry still is not a number.
- `pd.to_numeric(df['area'], errors='coerce')`: convert what can be converted and turn everything else (like `"unknown"`) into NaN, which you can then handle as in the previous section.

For repeated rows, `df.duplicated()` marks each row that is an exact copy of an earlier row, `df.duplicated().sum()` counts them, and `df.drop_duplicates()` removes them, keeping the first copy. A duplicated row is counted twice in every mean, count and model fit.

<DtypeDoctor />

<Mistake title="errors='coerce' can hide a disaster">
`pd.to_numeric(df['price'], errors='coerce')` on prices like `"585,000"` raises no error. It silently turns **every** price into NaN, because none of them is a number while it still has commas in it. Always run `df.isna().sum()` after a conversion to see how many values it turned into NaN.
</Mistake>

<Note>

Error messages differ slightly between pandas versions: pandas 3 says `str` where pandas 2 says `object`, and words its `TypeError`s differently. What matters is the kind of error (`TypeError`, `ValueError`, `KeyError`), which stays the same.

</Note>

<Tip>
You can often avoid the problem when you read the file: `pd.read_csv('flats.csv', thousands=',')` reads `"585,000"` as the number 585000. Then `value_counts()` (do the categories look right?), `sort_values()` (are the smallest and largest values believable?) and `describe()` (sensible min and max?) make quick sanity checks.
</Tip>

<PyRunner packages={['pandas']} code={`import io

<ExamTip>
Know the four conversion behaviours cold: `astype(int)` on `"450,000"` raises `ValueError`; `pd.to_numeric(..., errors='coerce')` turns bad entries into NaN (and makes the column float64); `drop_duplicates()` compares **whole rows** unless you pass `subset=`; and every one of these returns a new object, so assign it back.
</ExamTip>

<Takeaways>
- Count gaps with `df.isna().sum()` (per column; `isnull()` is the same method) or `df.isna().mean()` (fraction); test for NaN with `isna()`, never with `== np.nan`.
- `dropna()` removes rows (or columns with `axis=1`) and changes the shape; `fillna`, `ffill` and `interpolate` fill gaps and keep the shape. Dropping loses data, filling invents it.
- Use the median for unordered numbers with outliers (worked out on the training rows), `ffill` or `interpolate` for time series, and `df.drop(columns=[...])` for a column that is mostly empty.
- Numbers stored as text (dtype `object`) sort and compare wrongly; fix them with `str.replace` + `astype` or `pd.to_numeric(errors='coerce')`, then recount the NaNs.
- Remove repeated rows with `drop_duplicates()` before computing anything.
</Takeaways>
