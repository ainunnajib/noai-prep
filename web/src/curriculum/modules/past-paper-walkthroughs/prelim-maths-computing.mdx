### Why a zero eigenvalue means "singular" (Q15)

A recap from the [linear algebra drill](#/learn/prelim-speed-toolkit/drill-linear-algebra): an eigenvalue $\lambda$ of $A$ satisfies $Av = \lambda v$ for some non-zero $v$, and the determinant is the product of all the eigenvalues. So one eigenvalue of 0 means $Av = 0$: $A$ squashes a whole direction flat, $\det A = 0$, no matrix can undo it, and $A$ is singular. That squashed direction also costs **rank**, and in every case $\text{rank} \le \min(\text{rows}, \text{columns})$.

### The sigmoid derivative in four lines (Q34)

The <Term def="The S-shaped function σ(x) = 1/(1 + e^(−x)). It squeezes any number into the range 0 to 1.">sigmoid</Term> is $\sigma(x) = \dfrac{1}{1 + e^{-x}}$. Its derivative has a famous short form.

<Steps title="Derive σ′(x) = σ(x)(1 − σ(x))">
  <Step title="Rewrite as a power">
    $\sigma(x) = (1 + e^{-x})^{-1}$.
  </Step>
  <Step title="Chain rule: outer × inner">
    The outer function is $u^{-1}$, with derivative $-u^{-2}$. The inner function is $u = 1 + e^{-x}$, with derivative $-e^{-x}$. Multiply: $\sigma'(x) = -(1 + e^{-x})^{-2} \cdot (-e^{-x}) = \dfrac{e^{-x}}{(1 + e^{-x})^2}$.
  </Step>
  <Step title="Split the fraction">
    $\dfrac{e^{-x}}{(1 + e^{-x})^2} = \dfrac{1}{1 + e^{-x}} \cdot \dfrac{e^{-x}}{1 + e^{-x}}$. The first factor is $\sigma(x)$.
  </Step>
  <Step title="Spot 1 − σ">
    $1 - \sigma(x) = \dfrac{1 + e^{-x} - 1}{1 + e^{-x}} = \dfrac{e^{-x}}{1 + e^{-x}}$, which is the second factor. So $\sigma'(x) = \sigma(x)\,(1 - \sigma(x))$.
  </Step>
</Steps>

At $x = 0$, $\sigma(0) = \tfrac12$, so the slope is $\tfrac12 \times \tfrac12 = \tfrac14$, the steepest the sigmoid ever gets. As the [calculus drill](#/learn/prelim-speed-toolkit/drill-calculus-probability) showed, ten sigmoid layers then multiply the gradient by at most $(\tfrac14)^{10}$, less than a millionth (unless the weights compensate): the **vanishing gradient** problem behind Q44.

<Mistake title="σ′ = σ is the rule for eˣ">

The function that is its own derivative is $e^x$, not the sigmoid. The option "σ(x)" in Q34 is there to catch that mix-up. If in doubt, plug in $x = 0$: the true slope is 0.25, and "σ(x)" gives 0.5.

</Mistake>

<ExamTip title="Plug in a number">

When the options are formulas and you have forgotten the rule, evaluate every option at an easy point (here $x = 0$) and compare with what you know must be true there (the slope is positive and at most $\tfrac14$). Usually only one option survives, in about 10 seconds.

</ExamTip>

That quarter-slope bound is the whole of Q44. Try it before you open the answer.

### Newton's method: count before you guess (Q74)

A recap from the [conv and parameter drills](#/learn/prelim-speed-toolkit/drill-conv-and-params): Newton's step $w \leftarrow w - H^{-1} \nabla L$ needs the Hessian $H$, the $n \times n$ table of second derivatives, which costs $O(n^2)$ to store and $O(n^3)$ to invert. For Q74's $n = 10^4$ parameters that is $10^8$ entries and about $10^{12}$ operations **at every step**, while Adam needs only the forward and backward passes, so inverting the Hessian is the operation eating 95% of the time.

<Mistake title="Blaming something both optimisers do">

A 100× gap between two methods must come from something one of them does and the other does not. The forward pass, backpropagation and data loading are shared, so they are eliminated without any arithmetic.

</Mistake>

### Two computing traps, run for real (Q99 and Q115)

Q99 is about how pandas reads square brackets. Run this and watch three of the four options fail, each with a different error:

<PyRunner packages={['pandas']} code={`import pandas as pd

df = pd.DataFrame({"item": ["kaya toast", "kopi"], "total price": [2.5, 1.8]})
print(df["total price"].tolist())         # square brackets: works
print(df.loc[:, "total price"].tolist())  # .loc with rows first: also works

# eval runs a string as Python code; try/except catches the error so the loop carries on
for attempt in ["df.total price", "df('total price')", "df.loc['total price']"]:
    try:
        eval(attempt)
    except Exception as e:
        print(f"{attempt:24} -> {type(e).__name__}")  # :24 pads the text to 24 characters`} />

The second line shows why the paper's word "ONLY" is a little too strong: `df.loc[:, 'total price']` also works. Among the four options offered, though, square brackets are the only one that runs.

Q115 is about where PyTorch keeps gradients, the missing-`zero_grad()` trap from the [shapes and code drill](#/learn/prelim-speed-toolkit/drill-shapes-and-code). Every tensor created with `requires_grad=True` has a `.grad` slot, and `loss.backward()` **adds** the new gradient into it. Here $\text{loss} = w^2$, so $\frac{d\,\text{loss}}{dw} = 2w = 4$ at $w = 2$:

```python
import torch

w = torch.tensor(2.0, requires_grad=True)

for step in range(2):
    loss = w ** 2          # a fresh loss each time
    loss.backward()        # d(loss)/dw = 2w = 4
    print(f"after backward {step + 1}: w.grad = {w.grad.item()}")

w.grad.zero_()             # what optimiser.zero_grad() does for every parameter
loss = w ** 2
loss.backward()
print("after zero_grad and one backward:", w.grad.item())
```

```text
after backward 1: w.grad = 4.0
after backward 2: w.grad = 8.0
after zero_grad and one backward: 4.0
```

Read literally, though, "call `loss.backward()` twice" could mean twice on the *same* loss tensor. PyTorch frees the graph after the first backward pass to save memory, so that version fails:

```python
w = torch.tensor(2.0, requires_grad=True)
loss = w ** 2
loss.backward()
loss.backward()        # the SAME loss tensor again
```

```text
RuntimeError: Trying to backward through the graph a second time (or directly access saved tensors after they have already been freed). …
```

PyTorch's message goes on to name the fix: `loss.backward(retain_graph=True)` keeps the graph for a second pass.

The key accepts "Gradients accumulate", the intended reading (two training steps without zeroing). Knowing both behaviours means neither reading can surprise you.

<ExamTip title="Twin options cancel">

In Q115, "Second call overwrites first" and "Only second call's gradients are kept" say the same thing. A question has one right answer, so two options that mean the same must both be wrong. Look for twins whenever you are stuck.

</ExamTip>

## The time you bank

Why care whether Q1 takes 5 seconds or 30? Because the Prelim gives one clock for the whole paper, and in 2026 about half of the last block, Problem Solving, was long scenarios that took five times as long to read as anything else. Every second saved on a one-fact question is a second you can spend on a long scenario.

<TimeBank />

<ExamTip title="Two passes, not one">

Aim for about 25 seconds per short question on average and about 90 seconds per long scenario: that plan leaves several minutes spare. If a maths or computing question is not falling within about 30 seconds (the speed-mode cap from the [pacing lesson](#/learn/prelim-speed-toolkit/pacing-and-elimination)), it is probably one whose fact you have not learnt. Pick your best guess (no marks are deducted for wrong answers), flag it and move on. Come back only if the end of the paper leaves time.

This refines the plan you already have. The [exam format lesson](#/learn/start-here/exam-format-and-strategy) priced scenarios at 60 s, and the pacing lesson keeps a 15-minute reserve for them. Saving about 5 s on each short question is what lets you give each scenario 90 s. The checkpoints (Q50 by 30:00, Q100 by 60:00) stay the same.

</ExamTip>
