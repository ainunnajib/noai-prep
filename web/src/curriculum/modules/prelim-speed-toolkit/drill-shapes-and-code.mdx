## Shape annotation: write the shape on every line

<Analogy title="Labelling boxes when you move house">

When a family moves out of an HDB flat, the boxes labelled "kitchen: plates, fragile" go straight to the right room at the new place. The unlabelled ones have to be opened one by one to find out what is inside. Shapes are the labels of tensor code: write one next to each line and you never have to open a box to know what it holds.

</Analogy>

The habit is simple: for every line that makes an array or tensor, write its shape as a comment. Shapes in PyTorch images follow `(N, C, H, W)`: batch size, channels, height, width. You need only a handful of rules:

| Operation | Shape rule |
| --- | --- |
| `nn.Conv2d(C_in, C_out, k)` | $C$ becomes $C_\text{out}$; $H, W$ follow the size formula |
| pooling | $N$ and $C$ stay; $H, W$ shrink (halve for `MaxPool2d(2)`) |
| `x.flatten(1)` or `nn.Flatten()` | $(N, C, H, W) \to (N, C \cdot H \cdot W)$ |
| `nn.Linear(in, out)` | only the **last** dimension changes: in → out |
| `A @ B` | $(\dots, n, m)$ times $(\dots, m, p)$ gives $(\dots, n, p)$ |
| `sum`, `mean`, `max`, `argmax` over a dim | that dim disappears (`keepdim=True` keeps it as 1) |
| broadcasting | line shapes up from the right; a 1 stretches to match |
| `unsqueeze(i)`, `None` | insert a dimension of size 1 |
| `cat` / `stack` | `cat` grows an existing dim; `stack` adds a new one |
| `view` / `reshape` | same total count; `-1` means "whatever is left" |

Here is the example from the start of most CNN questions, run for real:

```python
import torch
import torch.nn as nn

# x: (N, C, H, W) = (32, 3, 28, 28)
x = torch.randn(32, 3, 28, 28)
# k=3, p=0, s=1
conv = nn.Conv2d(3, 16, kernel_size=3)
# h: (32, 16, 26, 26)
h = conv(x)
print(h.shape)
# keeps the batch: (32, 16*26*26)
print(nn.Flatten()(h).shape)
# trap: flattens the batch too
print(torch.flatten(h).shape)
# (3*3*3 + 1) * 16 parameters
print(sum(p.numel() for p in conv.parameters()))
```

```text
torch.Size([32, 16, 26, 26])
torch.Size([32, 10816])
torch.Size([346112])
448
```

The conv keeps the batch of 32, sets the channels to 16, and shrinks $28 \to 28 - 3 + 1 = 26$. Flattening each image gives $16 \times 26 \times 26 = 16 \times 676 = 10{,}816$ numbers.

<ShapeAnnotator />

<Mistake>

`torch.flatten(h)` with no second argument flattens **everything**, batch included: 346,112 numbers in one row instead of 32 rows of 10,816. Use `h.flatten(1)` or `nn.Flatten()`. When a model crashes with `mat1 and mat2 shapes cannot be multiplied`, check the flatten and the first `nn.Linear` first.

</Mistake>

## The trap catalogue

<Analogy title="Where learners fail the driving test">

Driving instructors in Singapore know the handful of junctions where learners fail most often, and they take you through them again and again. Code questions work the same way: the same dozen traps come back, and spotting the trap is usually the whole question.

</Analogy>

| Trap | What actually happens |
| --- | --- |
| `range` and slices | the end is **excluded**: `range(2, 8, 2)` is 2, 4, 6 |
| `//` and `%` | floor division rounds **down**: `-7 // 2` is −4, and `-7 % 3` is 2 |
| mutable default, `bag=[]` | the list is made once and **shared** by every call |
| aliasing, `b = a` | one list with two names; `[[0]*3]*2` repeats one row |
| views | a NumPy slice or a `view()` **shares memory**: writing to it changes the original |
| `*` vs `@` | `*` is element-wise; `@` is the matrix product |
| broadcasting | `(3,)` with `(3, 1)` stretches to `(3, 3)` |
| `loc` vs `iloc` | `loc[1:2]` includes label 2; `iloc[1:2]` excludes position 2 |
| integer dtypes | `torch.tensor([1, 2, 3])` infers `int64`, so `.mean()` fails and it cannot take gradients; `torch.Tensor([1, 2, 3])` (capital T) ignores that and makes the default `float32`; NumPy int arrays truncate 2.9 to 2 |
| no `zero_grad()` | `.backward()` **adds** to `.grad`, so gradients pile up |
| no `model.eval()` | dropout keeps dropping and batch norm keeps using batch statistics |
| softmax before `CrossEntropyLoss` | the loss already applies log-softmax; pass raw <Term def="The raw scores a classifier outputs before softmax turns them into probabilities.">logits</Term> |

Try the NumPy traps yourself. Change the slice to `a[1:3].copy()` and run it again.

And the two training-loop traps in PyTorch, run for real:

```python
import torch
import torch.nn as nn

w = torch.tensor(2.0, requires_grad=True)
for step in range(3):
    loss = 3 * w
    # no zero_grad: gradients pile up
    loss.backward()
    print("step", step, "grad", w.grad)

loss_fn = nn.CrossEntropyLoss()
# confident and right
logits = torch.tensor([[10.0, 0.0]])
target = torch.tensor([0])
# right: raw logits
print(loss_fn(logits, target))
# trap: softmax twice
print(loss_fn(logits.softmax(dim=1), target))
```

```text
step 0 grad tensor(3.)
step 1 grad tensor(6.)
step 2 grad tensor(9.)
tensor(4.5418e-05)
tensor(0.3133)
```

The true gradient of $3w$ is 3 at every step, but without `zero_grad()` the stored gradient grows 3, 6, 9. With the double softmax, a perfect prediction still has a loss of 0.31, so the model keeps being pushed and learns slowly.

<ExamTip>

A three-step routine for any code question: **(1)** name the trap the code is built around (end excluded? view? missing `zero_grad`?); **(2)** run the smallest case in your head, writing values or shapes on scrap paper; **(3)** match the exact print format: `tensor(9.)` is not `9`, and `[2 2 3]` (no commas) is a NumPy array, not a list. In the 2026 Final, 18 of the 20 MCQs showed a code snippet, and 11 of them were built around reading that code line by line.

<Takeaways>

- Write the shape next to every line of tensor code; a handful of rules (layers change one dim, reductions remove one, 1s broadcast) answer most shape questions.
- About a dozen traps recur: excluded ends, floor division, shared defaults and aliases, views, `*` vs `@`, broadcasting, `loc` vs `iloc`, integer dtypes, and the training-loop trio of `zero_grad`, `eval` and double softmax.
- When a snippet looks harmless, ask which trap the examiner planted: they rarely show code without one.

</Takeaways>
