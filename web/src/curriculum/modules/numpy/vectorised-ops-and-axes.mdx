Almost every line of a from-scratch model does one of two jobs: it **combines** arrays (adds them, multiplies them) or it **summarises** them (a total, an average, the best one). NumPy has two very different kinds of multiplication, and one small keyword, `axis`, that decides *which* numbers get summarised together. Mix them up and your code either crashes or, worse, quietly prints a wrong answer.

<Analogy title="Seat partners versus a handshake session">

Two classes sit in identical seating plans. **Element-wise** work is "the student in row 2, seat 3 of class A pairs up with the student in row 2, seat 3 of class B": everyone has exactly one partner, in the same position. A **matrix product** is more like an orientation handshake session: every *row* of class A meets every *column* of class B, and each meeting produces one number.

</Analogy>

## Element-wise: same position, same operation

When you write `+`, `-`, `*`, `/`, `**` or a comparison such as `>` between two arrays of the same shape, NumPy works <Term def="Applied separately at every position: the output at a position depends only on the inputs at that same position.">element-wise</Term>: position by position, as if you laid one array on top of the other.

```python
a = np.array([[1, 2, 3],
              [4, 5, 6]])
b = np.array([[2, 0, 1],
              [1, 3, 0]])
print(a * b)
```

```text
[[ 2  0  3]
 [ 4 15  0]]
```

In symbols, $(a * b)_{ij} = a_{ij} \times b_{ij}$. Here $i$ is the row number and $j$ the column number, so the entry in row $i$, column $j$ of the answer uses only the entries in row $i$, column $j$ of `a` and `b`. The answer has the same shape as the inputs, and there are no sums anywhere.

Functions such as `np.exp`, `np.sqrt` and `np.abs` act element-wise on a single array: `np.sqrt(np.array([1, 4, 9]))` gives `[1. 2. 3.]`. NumPy calls them <Term def="Universal functions: NumPy functions such as np.exp, np.sqrt and np.abs that apply to every element of an array in fast compiled code, with no Python loop.">ufuncs</Term>.

## Matrix product: rows meet columns

The `@` operator (or `np.dot(a, b)`, or `np.matmul(a, b)`) is the **matrix product** you met in the Vectors and matrices module. For $A$ with shape $(m, n)$ and $B$ with shape $(n, p)$:

$$
(AB)_{ij} = \sum_{k=1}^{n} A_{ik}\, B_{kj} = A_{i1}B_{1j} + A_{i2}B_{2j} + \dots + A_{in}B_{nj}
$$

- $i$ chooses a **row** of $A$ and $j$ chooses a **column** of $B$.
- $k$ walks along that row and down that column at the same time, multiplying partners. So the row and the column must have the same length $n$: **the number of columns of $A$ must equal the number of rows of $B$**.
- $\sum$ (sigma) adds up the $n$ products. That is exactly the dot product of row $i$ with column $j$.
- The result has shape $(m, p)$: the two outer numbers. The matching inner $n$ disappears.

(Maths counts from 1; NumPy counts rows and columns from 0, so the top-left entry is `out[0, 0]`.)

<ElementwiseVsMatmul />

<KeyIdea>

`a * b` multiplies matching positions and needs equal shapes (or *broadcastable* ones: next lesson). `a @ b` and `np.dot(a, b)` dot each row of `a` with each column of `b`, and need the inner sizes to match: $(m, n)$ @ $(n, p) \to (m, p)$.

</KeyIdea>

### Worked example: two friends, two hawker stalls

Wei Ling orders 2 chicken rice and 1 kopi; Hafiz orders 1 chicken rice and 3 kaya toast. Stall X and stall Y charge different prices (in dollars). One `@` gives every friend's bill at every stall.

```python
Q = np.array([[2, 1, 0],    # Wei Ling: chicken rice, kopi, kaya toast
              [1, 0, 3]])   # Hafiz
P = np.array([[4, 5],       # chicken rice at stall X, stall Y
              [1, 2],       # kopi
              [3, 2]])      # kaya toast
bills = Q @ P
```

<Steps title="Working out Q @ P by hand">
  <Step title="Check the shapes">
    `Q` is $(2, 3)$ (friends × dishes) and `P` is $(3, 2)$ (dishes × stalls). Inner sizes: $3 = 3$, so it works, and the answer is $(2, 2)$: friends × stalls.
  </Step>
  <Step title="Wei Ling at stall X: row 0 of Q · column 0 of P">
    $2 \times 4 + 1 \times 1 + 0 \times 3 = 8 + 1 + 0 = 9$.
  </Step>
  <Step title="Wei Ling at stall Y: row 0 · column 1">
    $2 \times 5 + 1 \times 2 + 0 \times 2 = 10 + 2 + 0 = 12$.
  </Step>
  <Step title="Hafiz: row 1 · each column">
    Stall X: $1 \times 4 + 0 \times 1 + 3 \times 3 = 13$. Stall Y: $1 \times 5 + 0 \times 2 + 3 \times 2 = 11$.
  </Step>
  <Step title="Read the answer">
    `bills` is $\begin{bmatrix} 9 & 12 \\ 13 & 11 \end{bmatrix}$. Each entry mixed a whole row of orders with a whole column of prices. By contrast `Q * P` crashes: shapes $(2, 3)$ and $(3, 2)$ are different, even though both hold 6 numbers.
  </Step>
</Steps>

For two 1-D vectors, `a @ b` is the ordinary dot product, a single number, and it equals `(a * b).sum()`: multiply partners element-wise, then add.

<Note title="np.dot, @ and np.matmul">

For 1-D and 2-D arrays all three agree. They differ only for 3-D and bigger arrays, where `@` treats the leading axes as a *batch* of matrices and `np.dot` does something else; so in your own code prefer `@`. Whatever the array, `*` is never the matrix product.

## Reducing along an axis

A <Term def="An operation that combines many numbers into fewer, such as sum, mean, max, min, argmax or std.">reduction</Term> squashes many numbers into fewer: `sum`, `mean`, `max`, `min`, `std`, and `argmax`/`argmin`, which return the **position** of the largest or smallest value rather than the value itself. Each one comes in two spellings that do the same thing: the function `np.mean(marks)` and the method `marks.mean()`. With no other argument, a reduction uses every element and returns one number.

A 2-D array has two <Term def="The directions you can move along in an array. In a 2-D array, axis 0 runs down the rows and axis 1 runs across the columns. The shape lists the length of each axis in order.">axes</Term>. **Axis 0** runs *down* the rows (its length is the number of rows, the first number in the shape); **axis 1** runs *across* the columns. The `axis=` argument says which direction to squash.

<Analogy title="Totalling a class mark sheet">

Rows are students, columns are subjects. Totalling **down** each column (`axis=0`) gives each *subject's* total over all students. Totalling **across** each row (`axis=1`) gives each *student's* total over all subjects.

</Analogy>

<AxisCollapse />

In symbols, for the mark sheet $x$ with rows $i$ and columns $j$:

$$
\texttt{x.sum(axis=0)}_j = \sum_{i} x_{ij}
$$

$$
\texttt{x.sum(axis=1)}_i = \sum_{j} x_{ij}
$$

With `axis=0` the row index $i$ is summed away, so only the column index $j$ is left: one answer per column. With `axis=1` the column index is summed away: one answer per row. On the mark sheet, `marks.sum(axis=0)` is `[21 21 24 18]` (subjects) and `marks.sum(axis=1)` is `[24 32 28]` (students).

<KeyIdea>

**The axis you name is the axis that disappears.** A $(3, 4)$ array reduced with `axis=0` becomes $(4,)$; with `axis=1` it becomes $(3,)$; with no axis it becomes a single number.

</KeyIdea>

<Mistake title="The axis=0 trap">

Many students read `axis=0` as "one answer per row". It is the opposite: `axis=0` moves *down the rows* and combines them, so you get one value **per column**. If you are unsure, do not try to picture it: write the shape, cross out the axis you named, and read off what is left.

</Mistake>

The same crossing-out rule works for any number of dimensions. Negative axes count from the end, so `axis=-1` always means the last axis, and you can name several axes at once with a tuple such as `axis=(1, 2)`.

<ShapeEraser />

### keepdims: keep the axis as a 1

`marks.mean(axis=1)` has shape $(3,)$, which is fine for printing but awkward for the next step. Suppose you want each student's marks relative to their own average. With `keepdims=True` the squashed axis stays, with length 1, so the result has shape $(3, 1)$: a column with one average per student, lined up with the rows of `marks`. Then `marks - marks.mean(axis=1, keepdims=True)` subtracts each student's own average from each of their marks. Without `keepdims`, NumPy tries to line up shapes $(3, 4)$ and $(3,)$ and raises `ValueError: operands could not be broadcast together`. The rule that decides which shapes line up is called **broadcasting**, and it is the whole of the next lesson.

<ExamTip>

Three patterns cover most Prelim questions on this lesson. **(1)** "`np.dot()` versus `*`": dot (and `@`) is the matrix product, or the dot product for 1-D arrays; `*` is element-wise. **(2)** Shape of a product: put the two shapes side by side, cover the touching inner pair with your thumb (they must be equal), and read off the outer pair: $(3 \times 2)(2 \times 4) \to 3 \times 4$. **(3)** Shape after a reduction: cross out the named axis. Also know the real spellings: `np.mean(arr)` or `arr.mean()`; there is no `np.avg` and no `arr.average()`.

</ExamTip>

<Note title="The same moves in PyTorch">

In the Final you will also use PyTorch tensors. `*` is still element-wise and `@` is still the matrix product. Reductions are spelt `dim=` and `keepdim=True` (PyTorch also accepts NumPy's `axis=` and `keepdims=`).

```python
import torch
t = torch.tensor([[6., 4., 6., 8.],
                  [8., 8., 10., 6.],
                  [7., 9., 8., 4.]])
print(t.sum(dim=0))
print(t.mean(dim=1, keepdim=True).shape)
```

```text
tensor([21., 21., 24., 18.])
torch.Size([3, 1])
```

</Note>

<Takeaways>

- `+ - * /` and ufuncs like `np.exp` are **element-wise**: same position in, same position out, same shape.
- `@` (and `np.dot`) is the **matrix product**: each output is a row of A dotted with a column of B, and $(m, n)$ @ $(n, p) \to (m, p)$. For two 1-D vectors, `a @ b` equals `(a * b).sum()`.
- Reductions (`sum`, `mean`, `max`, `argmax`, …) take `axis=`; **the named axis disappears** from the shape. On a 2-D array, `axis=0` gives one value per column and `axis=1` one per row.
- `argmax`/`argmin` return **positions**, not values.
- `keepdims=True` keeps the reduced axis as a 1, so the result lines up with the original array for the next calculation.

</Takeaways>
