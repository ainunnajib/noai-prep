In the Final you implement classic algorithms (K-means, k-nearest neighbours, a metric, a boosting step) in a Jupyter notebook, and hidden tests check what your functions return. The maths is rarely what costs marks. Turning "for every point, for every centroid…" into array code is, and so is returning *exactly* the format the test expects. This lesson gives you ten NumPy moves for that, with a cheat sheet at the end.

<Analogy title="The distance table on the MRT map">

Nobody works out the distance between two MRT stations from scratch each time: a table lists every station against every other, and you read off the cell you need. Most from-scratch algorithms start the same way: build the whole distance table in one go, then read answers off it.

</Analogy>

<Note title="The two algorithms in this lesson">

You met kNN in [classifying with boundaries and neighbours](#/learn/ai-first-look/classify-with-boundaries); K-means is new. Later modules cover both in depth; for now, just know what they do.

- **K-means** sorts unlabelled points into $k$ groups (clusters): put down $k$ centre points, give every point to its nearest centre, move each centre to the average of its points, and repeat until nothing changes.
- **k-nearest neighbours (kNN)** labels a new point by a vote among the $k$ labelled points closest to it.

Both start by measuring a lot of distances.

</Note>

## Moves 1 to 3: every distance at once

Say `X` holds $n$ points with $d$ features each, shape $(n, d)$, and `C` holds $k$ <Term def="The centre of a cluster: the average position of the points assigned to it.">centroids</Term> (cluster centres), shape $(k, d)$. K-means needs the <Term def="A table with one row per point and one column per centroid (or per training point): entry [i, j] is the distance from point i to centroid j.">distance matrix</Term> $D$ of shape $(n, k)$:

$$
D_{ij} = \sqrt{\sum_{f=1}^{d} \left(X_{if} - C_{jf}\right)^2}
$$

- $i$ picks a point (a row of `X`) and $j$ picks a centroid (a row of `C`).
- $f$ runs over the $d$ features. $X_{if} - C_{jf}$ is the gap between point $i$ and centroid $j$ in feature $f$.
- Square the gaps, add them up, take the square root: Pythagoras in $d$ dimensions, the <Term def="The straight-line distance between two points: the square root of the sum of squared differences in each coordinate.">Euclidean distance</Term>.

The beginner's version is a correct but slow double loop:

```python
D = np.zeros((n, k))
for i in range(n):
    for j in range(k):
        diff = X[i] - C[j]
        sq = (diff ** 2).sum()
        D[i, j] = np.sqrt(sq)
```

The NumPy version builds all $n \times k$ differences in one broadcast:

```python
# (n, d) -> (n, 1, d)
A = X[:, None, :]
# (k, d) -> (1, k, d)
B = C[None, :, :]
# (n, k, d): every X[i] - C[j]
diff = A - B
# sum the d features -> (n, k)
sq = (diff ** 2).sum(axis=-1)
D = np.sqrt(sq)
# nearest centroid -> (n,)
labels = D.argmin(axis=1)
```

`X[:, None, :]` inserts a length-1 axis in the middle, turning $(n, d)$ into $(n, 1, d)$; `C[None, :, :]` turns $(k, d)$ into $(1, k, d)$. Lined up from the right, $d$ matches $d$ and the two 1s stretch, so `diff[i, j]` is exactly `X[i] - C[j]` for every pair.

  <Step title="The data">
    `X = [[0, 0], [2, 1], [5, 4]]`, shape $(3, 2)$. `C = [[1, 0], [4, 4]]`, shape $(2, 2)$. So `diff` has shape $(3, 2, 2)$ and `D` will be $(3, 2)$.
  </Step>
  <Step title="Squared distances, row 0: point (0, 0)">
    To $(1, 0)$: $(0-1)^2 + (0-0)^2 = 1$. To $(4, 4)$: $(-4)^2 + (-4)^2 = 32$.
  </Step>
  <Step title="Rows 1 and 2">
    Point $(2, 1)$: $1^2 + 1^2 = 2$ and $(-2)^2 + (-3)^2 = 13$. Point $(5, 4)$: $4^2 + 4^2 = 32$ and $1^2 + 0^2 = 1$.
  </Step>
  <Step title="Assign">
    Squared distances $\begin{bmatrix} 1 & 32 \\ 2 & 13 \\ 32 & 1 \end{bmatrix}$; the smallest in each row is in column 0, 0, 1, so `labels` is `[0 0 1]`. Square roots cannot change which entry is smallest, so for `argmin` you may skip `np.sqrt`.
  </Step>
</Steps>

<Mistake title="Forgetting the None">

`X - C` with shapes $(100, 2)$ and $(3, 2)$ fails: $100$ against $3$. With $(4, 2)$ and $(4, 2)$ it runs, but computes point 0 minus centroid 0, point 1 minus centroid 1 and so on: row by row, not all pairs. The `None`s are what make "every pair" happen.

</Mistake>

## Moves 4 to 6: neighbours, groups and votes

**k-nearest neighbours.** Build the distance matrix from every test point to every training point, shape $(m, n)$ ($m$ test points, $n$ training points). `np.argsort` returns the positions that would sort each row, so its first $k$ columns are the nearest neighbours; indexing the training labels with them gives the labels that vote.

```python
# (m, n): nearest first
order = np.argsort(D, axis=1)
# (m, 3): the 3 nearest
idx = order[:, :3]
# (m, 3): their labels
votes = y_train[idx]
# (m,): the most common label
pred = np.array(
    [np.bincount(v).argmax()
     for v in votes])
```

`np.bincount(v)` counts how often each whole number 0, 1, 2, … appears in `v`, so its `.argmax()` is the most common label. `np.unique(y, return_counts=True)` works for any labels, returning the sorted distinct values and their counts.

<Note title="Big data and ties">

The broadcast builds the whole $(m, n, d)$ difference array before summing: about 3.8 TB for MNIST (10,000 test against 60,000 training images of 784 pixels, float64). Process test points in chunks, or use $\lVert x - c \rVert^2 = \lVert x \rVert^2 + \lVert c \rVert^2 - 2\, x \cdot c$, which needs one matrix product. On ties, `np.argsort`'s default may order equal distances either way; `kind='stable'` keeps the lower index first.

</Note>

**K-means update.** After assigning labels, each centroid moves to the mean of its points. A <Term def="An array of True/False values with the same length as the data, used to pick out the rows where the condition is True.">boolean mask</Term> picks one cluster's rows:

```python
for j in range(k):
    # (n,): True if in cluster j
    mask = labels == j
    # empty: keep the old C[j]
    if not mask.any():
        continue
    # (d,): mean of cluster j
    C[j] = X[mask].mean(axis=0)
```

A short loop over the $k$ clusters is fine: $k$ is small, and the expensive $n \times k$ part is already vectorised. The `if` guards an empty cluster, where `X[mask]` has shape $(0, d)$ and its mean is `nan` ("not a number"); the old centroid is kept instead. And `C` must be a **float** array, or `C[j] = ...` silently cuts the means to whole numbers: start from `X[idx].astype(float)`.

## Moves 7 to 9: where, sign and one-line metrics

<ArgOpsPlayground />

What the playground shows:

- `argmax`/`argmin` return a **position**; `max`/`min` return a **value**. Cluster assignment needs the position. With ties, the *first* position wins.
- `np.where(cond, a, b)` picks from `a` where `cond` is True and from `b` elsewhere: `np.where(p >= 0.5, 1, 0)` turns probabilities into class predictions, and `np.where(z > 0, z, 0)` is ReLU.
- `np.sign(r)` gives $-1$, $0$ or $1$. With `r = y - guess`, $+1$ means the guess is too low, $-1$ too high and $0$ exact: the way to nudge it.
- To pick **one** number $c$ to stand for all of `y`, the <Term def="The middle value once the numbers are sorted; with an even count, the average of the two middle values.">median</Term> (`np.median(y)`) makes the total gap $\sum |y_i - c|$ smallest and the **mean** makes the total *squared* gap $\sum (y_i - c)^2$ smallest. One extreme value drags the mean far but barely moves the median.
- `np.clip(p, 1e-7, 1 - 1e-7)` squeezes probabilities away from exactly 0 and 1, where `np.log` gives `-inf`.
- Metrics take one line: accuracy `(pred == y).mean()` (True counts as 1), mean squared error `((pred - y) ** 2).mean()`, mean absolute error `np.abs(pred - y).mean()`.

### Random starts you can repeat

Here the start was the first two points; usually it is **random**. A computer's random numbers follow a recipe that starts from a <Term def="The starting number of a random number generator. The same seed always produces the same sequence of 'random' numbers.">seed</Term>: the same seed always gives the same numbers, so you, and a grader, can reproduce a "random" result exactly.

```python
import numpy as np

# a generator started from seed 0
rng = np.random.default_rng(0)
# 5 whole numbers from 0 to 9
a = rng.integers(0, 10, size=5)
# same seed, same numbers
rng = np.random.default_rng(0)
b = rng.integers(0, 10, size=5)
print(a)
print(b)
# 2 numbers from a bell curve
print(rng.normal(0, 1, size=2))
# 0 to 5 in a shuffled order
print(rng.permutation(6))

X = np.array([[1, 1], [2, 1],
              [8, 9], [9, 8],
              [1, 2]])
rng = np.random.default_rng(0)
# 2 different row numbers
n = len(X)
idx = rng.choice(n, 2,
                 replace=False)
# starting centroids, as floats
C = X[idx].astype(float)
print(idx)
print(C)
```

```text
[8 6 5 2 3]
[8 6 5 2 3]
[ 0.10490012 -0.53566937]
[0 2 4 3 5 1]
[3 4]
[[9. 8.]
 [1. 2.]]
```

- `rng.choice(n, k, replace=False)` picks $k$ *different* positions out of $n$: the standard way to choose starting centroids.
- `rng.permutation(n)` shuffles 0 to $n - 1$. Index both `X[idx]` and `y[idx]` with it, so every example keeps its label.
- Each Final task gives you a **stub**: the starter function, with its name, its inputs and a **docstring** (the description in triple quotes of what it must return). If a stub sets a seed (older code writes `np.random.seed(0)`), make exactly the random calls it shows, in order: one extra call shifts every number after it.

## Move 10: return exactly what the grader expects

A grader compares your function's result with a stored answer, either **exactly** (`==`) or within a small **tolerance** (`np.allclose`). You usually cannot see which, so match the stub to the letter: right **type**, **shape** and **rounding**.

<OutputFormatChecker />

<Steps title="A checklist before you submit a function">
  <Step title="Type">
    "A list" means `.tolist()`; "a float" means `float(x)`; "a list of tuples" means `[tuple(r) for r in arr.tolist()]`. An array is not a list, and a tuple never equals a list.
  </Step>
  <Step title="Shape">
    `(n,)` and `(n, 1)` hold the same numbers but are different answers. Print `.shape` and compare it with the docstring's example.
  </Step>
  <Step title="Rounding">
    Round only the final output, with `np.round(x, 4)` (or `round(float(x), 4)` for one number); rounding mid-calculation adds errors. NumPy rounds exact halves to the nearest **even** digit: `np.round(2.5)` is `2.0`.
  </Step>
  <Step title="Edge cases">
    Empty clusters, division by zero (<Term def="The fraction of predicted positives that are right: correct positive predictions divided by all positive predictions. The model evaluation module covers it.">precision</Term> when nothing is predicted positive, IoU when a class appears nowhere), and `-0.0` from rounding a tiny negative. `-0.0 == 0.0` is `True`, so it matters only when output is compared as text; adding `0.0` removes it.
  </Step>
  <Step title="Return, don't print">
    The test sees only what your function **returns**: printing the perfect answer and returning `None` scores zero.
  </Step>
</Steps>

Edge cases are where a metric's *definition* matters. Mean <Term def="Intersection over Union: the pixels that both prediction and truth mark as a class, divided by the pixels that either marks as that class.">IoU</Term> averages, over the classes, overlap divided by combined area: $\frac{|\text{pred} \cap \text{true}|}{|\text{pred} \cup \text{true}|}$. A class in *neither* prediction nor ground truth gives the undefined $\frac{0}{0}$, so it is usually skipped; a class predicted but absent still counts, with IoU 0.

<Takeaways>

- `X[:, None, :] - C[None, :, :]` gives every pairwise difference, shape $(n, k, d)$; square, `sum(axis=-1)` and `np.sqrt` give the $(n, k)$ distance matrix.
- `D.argmin(axis=1)` assigns clusters, `np.argsort(D, axis=1)[:, :k]` finds neighbours, and `X[labels == j].mean(axis=0)` updates a centroid (guard against empty clusters).
- arg-functions return **positions**; `np.where`, `np.sign`, `np.unique`/`np.bincount` and one-line metrics cover most of the rest.
- Return exactly what the stub asks for: type (`.tolist()`, `float`), shape, and `np.round(x, 4)` on the final output. Return, don't print.

</Takeaways>
