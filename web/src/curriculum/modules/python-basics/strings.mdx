Text is everywhere in AI: chat messages, product reviews, prompts, the answers a chatbot writes. Before any model can use text, a program has to cut it up, clean it and split it into pieces. In Python, text is a **string**, and this lesson gives you the tools to work with it: indexing, slicing, string methods and f-strings.

## A string is a sequence of characters

A string is text written inside quotes. Single and double quotes mean exactly the same thing, so you can pick whichever lets you write the text you need:

```python
city = "Singapore"
reply = "can't lah"      # double quotes, so the ' inside is fine
empty = ""               # the empty string: no characters at all
```

Python sees a string as a <Term def="An ordered row of items where each item has a fixed position, like the characters of a string or the items of a list.">sequence</Term> of characters in a fixed order. A character is anything you can type: a letter, a digit, a space, a punctuation mark, even an emoji. The built-in function `len()` counts them:

```python
print(len("Hello"))
print(len("Hi there"))   # the space counts
print(len(""))
```

```text
5
8
0
```

### Indexing: one character at a time

Every character has a numbered position called its <Term def="The position number of an item in a sequence. Python starts counting at 0, so the first item has index 0.">index</Term>, and Python counts from **0**. So in `city = "Singapore"`, `city[0]` is `'S'`, `city[1]` is `'i'`, and the last character, `'e'`, is `city[8]`: the length is 9, so the last index is $9 - 1 = 8$.

Python also numbers the characters **from the end** with negative indices: `city[-1]` is the last character, `city[-2]` the one before it, and so on. In general `s[-k]` is the same as `s[len(s) - k]`.

<Analogy title="Cutting a strip of kueh lapis">

Lay a strip of kueh lapis on a ruler. The ruler's marks 0, 1, 2, … sit **between** the layers, and the first layer starts at mark 0. Cut at mark 1 and at mark 4 and you get the 3 layers between the cuts ($4 - 1 = 3$). Python's slice numbers work exactly like those marks: `s[1:4]` cuts at gap 1 and gap 4, so it takes the characters in between. You will see the gaps as the ruler under the boxes below.

</Analogy>

### Slicing: a range of characters

A <Term def="A part of a sequence picked out with s[start:stop], from position start up to, but not including, position stop.">slice</Term> takes several characters at once. Its general form has three numbers, each optional:

$$
s[\,\text{start} : \text{stop} : \text{step}\,]
$$

- **start** is the first position taken. Leave it out to start at the beginning.
- **stop** is where the slice ends: the character *at* `stop` is **not** included. Leave it out to go to the very end.
- **step** is how far to move each time (1 if you leave it out). A step of 2 takes every second character; a negative step walks backwards.
- For a simple slice `s[a:b]` with $0 \le a \le b \le$ `len(s)`, the result has exactly $b - a$ characters.

Thinking of the numbers as sitting on the **gaps** between characters (like the handles in the visual) makes the rule easy: `s[1:4]` cuts at gap 1 and gap 4, and keeps what lies between.

<Steps title="Slicing 'Singapore' by hand">
  <Step title="Write the indices">
    S, i, n, g, a, p, o, r, e have indices 0 to 8 (or −9 to −1 from the end).
  </Step>
  <Step title="s[1:4]">
    Positions 1, 2 and 3 (not 4): `'ing'`. That is $4 - 1 = 3$ characters.
  </Step>
  <Step title="s[:5] and s[5:]">
    `s[:5]` is positions 0 to 4: `'Singa'`. `s[5:]` is position 5 to the end: `'pore'`. Glued back together, `s[:5] + s[5:]` is the whole string again.
  </Step>
  <Step title="s[-4:]">
    Start 4 from the end, at index $9 - 4 = 5$, and go to the end: `'pore'` again.
  </Step>
  <Step title="s[::-1]">
    No start or stop, step −1: the whole string backwards, `'eropagniS'`.
  </Step>
</Steps>

Two more rules. Asking for a single index that does not exist, such as `s[20]`, raises `IndexError: string index out of range`. But slices are forgiving: `s[3:100]` simply stops at the end and gives `'gapore'`.

## Strings never change

Try to change one character of a string and Python refuses:

```python
city = "Singapore"
city[0] = "J"
```

```text
TypeError: 'str' object does not support item assignment
```

Strings are <Term def="Cannot be changed after it is created. Operations on an immutable value make a new value instead.">immutable</Term>: once a string exists, it can never be changed. To get a different string you build a **new** one, for example `"J" + city[1:]` gives `'Jingapore'`. Python makes strings immutable on purpose: a string can then be shared safely, because nothing can change it behind your back. The lists you will meet at the end of this module are the opposite: they are mutable, so you *can* change their items in place.

## String methods: tools that return new strings

A <Term def="A function that belongs to a value and is called with a dot after it, like text.upper(). It works on that value.">method</Term> is a function that belongs to a value. You call it with a dot: `text.upper()`. Strings come with dozens of methods; these are the ones you will use most:

| Method: what it returns | Example → result |
|---|---|
| `.upper()` / `.lower()`: the text in capitals / small letters | `'Hi'.upper()` → `'HI'` |
| `.strip()`: the text without spaces at either end | `' hi '.strip()` → `'hi'` |
| `.replace(old, new)`: every `old` swapped for `new` | `'lah'.replace('a', 'e')` → `'leh'` |
| `.split()`: a **list** of the words | `'can or not'.split()` → `['can', 'or', 'not']` |
| `sep.join(words)`: the words glued together with `sep` | `'-'.join(['a', 'b'])` → `'a-b'` |
| `.count(sub)`: how many times `sub` appears | `'banana'.count('a')` → `3` |

<Analogy title="A photo filter app">

When you apply a filter in a photo app, you get a new, edited copy, and the original photo is still in your gallery. String methods work the same way: `text.upper()` hands you a new string and leaves `text` exactly as it was.

</Analogy>

<MethodChain />

The chain at the start of the visual, `text.strip().lower().split()`, is a real first step in how AI reads language: tidy the text, make capitals consistent, then split it into pieces. Splitting text into the units a model works with is called <Term def="Splitting text into tokens, the units a language model reads: whole words, or smaller pieces of words. Each token is then turned into a number.">tokenisation</Term>. `.split()` gives whole words; the tokenisers inside modern language models also split rare words into smaller subword pieces, but the idea is the same.

<Mistake title="Calling a method and throwing the answer away">

```python
name = "alice"
name.upper()
print(name)        # still alice
```

`name.upper()` made the new string `'ALICE'`, but nothing kept it, so it was thrown away. Save the result: `name = name.upper()`.

</Mistake>

## f-strings: putting values into text

Often you want to build a sentence out of values, such as a name and a score. Put an `f` just before the opening quote and write any expression inside curly brackets: Python works out each one and drops its value into the text. This is an <Term def="A string with an f before the opening quote. Expressions inside curly brackets are worked out and their values inserted into the text.">f-string</Term> (f for *formatted*).

```python
name = "Wei Ling"
avg = (85 + 72 + 78) / 3
print(name, "scored", avg)
print(f"{name} scored {avg:.2f} on average")
print(f"{name.upper()} has {len(name)} characters")
```

```text
Wei Ling scored 78.33333333333333
Wei Ling scored 78.33 on average
WEI LING has 8 characters
```

The part after the colon in `{avg:.2f}` is a **format specification**: `.2f` means "show this as a float with 2 decimal places", rounding as needed. It only changes how the number is *shown*; `avg` itself still holds all its digits.

<Takeaways>

- A string is a sequence of characters. `len(s)` counts them; `s[0]` is the first and `s[-1]` the last; a missing index raises `IndexError`.
- `s[start:stop:step]` includes `start` but stops just *before* `stop`; `s[a:b]` has $b - a$ characters, and `s[::-1]` reverses. Lists and NumPy arrays use the same rules.
- Strings are immutable: methods like `.upper()`, `.strip()`, `.replace()` return new strings, so save the result.
- `.split()` turns text into a list of words (the simplest tokeniser) and `sep.join(words)` glues them back.
- f-strings put values into text: `f"{name} scored {avg:.2f}"`, where `:.2f` shows 2 decimal places.

</Takeaways>
