A program that cannot remember anything is not much use. To keep a score, add up marks or train a model, Python needs to **store** values, know what **kind** of value each one is, and **calculate** with them. Those are this lesson's three ideas: variables, types and arithmetic. Every line of AI code you will ever read uses all three.

## Variables: names for values

```python
score = 42
print(score + 8)
```

```text
50
```

The line `score = 42` is an <Term def="A line that gives a name to a value, written name = value. The name goes on the left of the = sign.">assignment</Term>. It creates a <Term def="A name that refers to a value, so you can use the value later by writing the name.">variable</Term>: the name `score` now refers to the value `42`, and anywhere you write `score` afterwards, Python uses 42.

Read `=` as "now refers to", **not** as "equals". It is an instruction with two steps:

1. Work out the right-hand side.
2. Make the name on the left refer to that result. If the name already referred to something, it moves.

That is why `x = x + 1` makes sense in Python even though it is nonsense as a maths equation: "work out `x + 1` using the current `x`, then make `x` refer to the answer".

<Analogy title="Choping a seat with a tissue packet">

At a hawker centre you "chope" a seat by leaving a tissue packet on it. The packet (the name) is not the seat (the value); it just marks which seat is yours. You can pick the packet up and put it on another seat, and two friends can put their packets on the same seat. Python's names work exactly like that.

</Analogy>

<VariableBoxes />

<KeyIdea>

`=` means *assign*, not *is equal to*: work out the right-hand side, then point the name on the left at the result. Moving one name never moves any other name.

</KeyIdea>

A few rules for names:

- Use letters, digits and underscores, but don't start with a digit: `score2` is fine, `2score` is a `SyntaxError`.
- Names are case-sensitive: `Score` and `score` are two different variables.
- No spaces. Python programmers join words with underscores: `exam_score`.
- Python's own keywords, such as `if`, `for`, `while`, `class`, `True` and `None`, cannot be names: `class = 3` is a `SyntaxError`.
- Don't reuse built-in names such as `print`, `type` or `str` for your own variables. After `str = "hi"`, the line `str(5)` fails with `TypeError: 'str' object is not callable` ("not callable" means it can no longer be called like a function).

### Worked example: a trace table

To work out what a program does with its variables, keep a **trace table**: one column per variable, one row per line, updated as you go.

```python
a = 3
b = a * 2
a = a + b
b = b - 1
```

| After line | `a` | `b` | why |
|---|---|---|---|
| 1 | 3 | (none) | `b` does not exist yet |
| 2 | 3 | 6 | right side first: $3 \times 2 = 6$ |
| 3 | 9 | 6 | right side first, with the current values: $3 + 6 = 9$ |
| 4 | 9 | 5 | $6 - 1 = 5$ |

<Mistake title="Writing the assignment backwards">

The name always goes on the **left**. `5 = x` is a `SyntaxError` ("cannot assign to literal"). And a single `=` never *checks* whether two things are equal: that is `==`, which you will meet in the lesson on decisions.

</Mistake>

## Types: what kind of value is it?

Every value in Python has a <Term def="The kind of value something is, such as a whole number, a decimal number, text or True/False. The type decides what you can do with the value.">type</Term>. You will use four basic types all the time:

| Type | What it holds | Examples |
|---|---|---|
| `int` (integer) | whole numbers, positive or negative | `42`, `-7`, `0` |
| `float` (floating-point number) | numbers with a decimal point | `3.0`, `-0.5`, `2.5e3` |
| `str` (string) | text, written inside quotes | `'hi'`, `"42"`, `''` |
| `bool` (Boolean) | truth values | `True`, `False` |

The built-in function `type()` tells you the type of any value. ("Class" is Python's word for a type.)

```python
print(type(42))
print(type(3.0))
print(type("42"))
print(type(True))
```

```text
<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
```

Two details catch people out. First, **quotes make a string**, whatever is inside them: `"42"` is text, not a number. Second, `2.5e3` is <Term def="A short way to write very big or very small numbers: 2.5e3 means 2.5 × 10³ = 2500, and 1e-3 means 1 × 10⁻³ = 0.001.">scientific notation</Term> for $2.5 \times 10^3 = 2500.0$, and it is always a float. You will see it constantly in AI code: a learning rate of `1e-3` means $0.001$.

<TypeSorter />

### Why types matter

What an operator does depends on the types it is given:

- `3 + 3` adds numbers: `6`.
- `'3' + '3'` joins two strings end to end, called <Term def="Joining strings end to end with +, so 'ab' + 'cd' gives 'abcd'.">concatenation</Term>: `'33'`.
- `'3' * 3` repeats a string: `'333'`.
- `'3' + 3` is a `TypeError`: should `+` add or join? Python refuses to guess.

To fix a type mismatch, **convert** the value with a function named after the type you want:

| Conversion | Result |
|---|---|
| `int('42')` | `42`: it reads whole-number text |
| `int(3.99)` | `3`: it chops off the decimal part; it does **not** round |
| `float('2.5')` | `2.5`: it reads decimal text |
| `float(3)` | `3.0` |
| `str(42)` | `'42'`: number to text |
| `int('3.5')` | `ValueError` (the type is fine, but this value cannot be converted): `int()` only reads whole-number text |
| `bool(0)`, `bool('')` | `False`: zero and empty text are `False`; almost everything else is `True` |

<TypeMixer />

<Mistake title="Text that looks like a number is still text">

Values that come from outside your program, such as numbers in a file or something a user types in, usually arrive as strings. `'3' + 3` fails, and `'3' * 3` silently gives `'333'` instead of 9. When a number behaves strangely, check its type with `type()` and convert it with `int()` or `float()`.

</Mistake>

## Arithmetic: Python as a calculator

Python has seven basic arithmetic operators (there is also `@`, for matrix multiplication, which you will use with NumPy later). Here they all are with the same two numbers:

| Operator | Name | Example | Result |
|---|---|---|---|
| `+` | add | `7 + 2` | `9` |
| `-` | subtract | `7 - 2` | `5` |
| `*` | multiply | `7 * 2` | `14` |
| `/` | divide | `7 / 2` | `3.5` |
| `//` | floor division | `7 // 2` | `3` |
| `%` | remainder (modulo) | `7 % 2` | `1` |
| `**` | power | `7 ** 2` | `49` |

Three rules about the result's type:

- `/` **always** gives a float, even when the answer is whole: `6 / 3` is `2.0`.
- If either number is a float, the result is a float: `3 + 3.0` is `6.0`.
- Powers use `**`. The `^` key does something else entirely in Python (`2 ^ 3` is `1`), so never use it for powers.

### `//` and `%`: sharing kueh

<Analogy title="Sharing kueh">

You have 7 kueh and 2 friends. Deal them out one each, round after round, until there are not enough left for another full round. Each friend gets 3: that is `7 // 2`. One is left over in the box: that is `7 % 2`.

</Analogy>

<KuehSplitter />

For whole numbers $a$ and $b$ (with $b \neq 0$), the two operators are tied together by one equation:

$$
a = (a \,/\!/\, b) \times b + (a \,\%\, b)
$$

- $a \,/\!/\, b$, read "a floor-divided by b", is how many **whole** times $b$ fits into $a$: the division rounded **down**. For negative numbers, down means towards minus infinity: `-7 // 2` is `-4`, not `-3`, and then `-7 % 2` is `1`, so $-4 \times 2 + 1 = -7$ still holds.
- $a \,\%\, b$, read "a mod b", is the **remainder**: what is left over. When $b$ is positive it is always between $0$ and $b - 1$.
- In words: full rounds times friends, plus the leftovers, gives back all the kueh. For 7 and 2: $3 \times 2 + 1 = 7$.

These two operators are more useful than they look. `n % 2` is 0 for even numbers and 1 for odd ones; `n % 10` is the last digit of `n`; and `//` with `%` together split a quantity into units.

<Steps title="Convert 135 minutes into hours and minutes">
  <Step title="Whole hours: 135 // 60">
    60 fits into 135 twice (120), and a third time would be 180, too many. So `135 // 60` is `2` hours.
  </Step>
  <Step title="Leftover minutes: 135 % 60">
    $135 - 2 \times 60 = 135 - 120 = 15$, so `135 % 60` is `15` minutes.
  </Step>
  <Step title="Check with the equation">
    $2 \times 60 + 15 = 135$. ✓ So 135 minutes is 2 h 15 min.
  </Step>
</Steps>

### Order of operations

When an <Term def="Any piece of code that Python works out to a single value, such as 2 + 3 * 4, x + 1 or 17 // 5.">expression</Term> has several operators, Python follows strict <Term def="The rules that decide which operator in an expression is worked out first, like BODMAS in school maths.">precedence</Term> rules, much like BODMAS in school maths. From first to last:

1. **Brackets** `( )`
2. **Power** `**`, which works **right to left**: `2 ** 3 ** 2` is `2 ** 9`, which is `512`.
3. A **minus sign in front** of a number, as in `-x`. Because `**` comes first, `-2 ** 2` is $-(2^2) = -4$. (A minus straight after `**` belongs to the exponent: `2 ** -1` is $2^{-1} = 0.5$.)
4. `*`, `/`, `//` and `%`, from left to right.
5. `+` and `-`, from left to right: `10 - 4 - 3` is `(10 - 4) - 3`, which is `3`.

<ExpressionTree />

<Steps title="Evaluate 2 + 3 * 4 ** 2 by hand">
  <Step title="Power first">
    `4 ** 2` is $4^2 = 16$. The expression becomes `2 + 3 * 16`.
  </Step>
  <Step title="Then multiply">
    `3 * 16` is $48$. The expression becomes `2 + 48`.
  </Step>
  <Step title="Add last">
    `2 + 48` is `50`. With brackets, `(2 + 3) * 4 ** 2` is $5 \times 16 = 80$ instead.
  </Step>
</Steps>

<Note title="Floats are approximate">

`print(0.1 + 0.2)` shows `0.30000000000000004`. Computers store floats in binary, and 0.1 cannot be written exactly in binary, just as $\tfrac{1}{3}$ cannot be written exactly in decimal, so tiny errors appear in the 16th or 17th digit. Never expect two floats to be *exactly* equal: round them (`round(0.1 + 0.2, 2)` gives `0.3`) or check that they are very close.

</Note>

<Takeaways>

- `name = value` makes the name refer to the value, after working out the right-hand side. Reassigning one name never moves another.
- Four basic types: `int`, `float`, `str` and `bool`. Quotes make a string; a decimal point (or an `e`) makes a float; `type()` tells you which.
- Mixing types: `int` with `float` gives a `float`; `str + int` is a `TypeError`. Convert with `int()`, `float()` and `str()`.
- `/` always gives a float, `//` divides and rounds down, and `%` gives the remainder; the rule $a = (a /\!/ b) \times b + a \,\%\, b$ ties `//` and `%` together.
- Precedence: brackets, then `**` (right to left), then a leading minus, then `* / // %`, then `+ -`. Floats are approximate: `0.1 + 0.2` is `0.30000000000000004`.

</Takeaways>
