## The formula on one line

Fix one class $c$, say Forest. Let $P_c$ be the set of pixels the model **predicted** as $c$ and $T_c$ the pixels that are **truly** $c$. Then

$$
\text{IoU}_c = \frac{|P_c \cap T_c|}{|P_c \cup T_c|} = \frac{TP}{TP + FP + FN}
$$

The bars $|\cdot|$ mean "the number of pixels in". The top, the <Term def="The pixels in both sets: predicted as the class AND truly that class.">intersection</Term>, counts pixels where prediction and truth agree on $c$. The bottom, the <Term def="The pixels in at least one of the sets: predicted as the class OR truly that class, or both.">union</Term>, counts every pixel that either of them calls $c$. In confusion-matrix words, for this one class, $TP$ (true positives) are correct $c$ pixels, $FP$ (false positives) are pixels wrongly predicted as $c$, and $FN$ (false negatives) are $c$ pixels the model missed. **Mean IoU** averages $\text{IoU}_c$ over the classes, and the task's rule is to **leave out any class whose union is 0**: a class that appears in neither map has $\text{IoU} = 0/0$, which is undefined.

Why not just count correct pixels? The notebook's own example: on a map that is 90% Forest, a lazy model that always says "Forest" gets **90% pixel accuracy**. Its mIoU is $(0 + 0.90)/2 = 0.45$: Urban has intersection 0 (it never predicts Urban), and Forest has intersection 90 and union 100. Accuracy rewards ignoring the rare class; IoU does not, because it never counts the correctly ignored pixels. ([Segmentation metrics](#/learn/vision-tasks/segmentation-metrics) covers IoU, Dice and this trap in more depth.)

## From the formula to tensor code: masks and sums

Each set becomes a <Term def="A tensor of True/False values with the same shape as the label map, e.g. pred == 1 is True exactly where the prediction says class 1.">boolean mask</Term>. `pred_flat == cls` is a tensor that is `True` wherever the prediction says `cls`. Then `p & t` (and) is `True` where both are, `p | t` (or) where at least one is, and `.sum()` counts the `True`s, because `True` counts as 1. Before that, `reshape(-1)` flattens the `(B, H, W)` maps into one long row of pixels, so a single comparison handles every image in the batch at once. That is what the task means by <Term def="Doing a calculation with whole-tensor operations (comparisons, &, |, sum) instead of a Python for loop over individual elements. Much faster, and required by the task.">vectorised</Term>: the only Python loop is over the 2 classes, never over pixels or images.

  <Step title="Flatten">
    `pred = [[0, 0], [1, 1]]` becomes `[0, 0, 1, 1]`, and `true = [[0, 1], [1, 1]]` becomes `[0, 1, 1, 1]`.
  </Step>
  <Step title="Class 0 (Urban)">
    `p = [T, T, F, F]`, `t = [T, F, F, F]`. Both True only at position 0: intersection 1. At least one True at positions 0 and 1: union 2. $\text{IoU}_0 = 1/2 = 0.5$.
  </Step>
  <Step title="Class 1 (Forest)">
    `p = [F, F, T, T]`, `t = [F, T, T, T]`. Intersection: positions 2 and 3, so 2. Union: positions 1, 2 and 3, so 3. $\text{IoU}_1 = 2/3 \approx 0.667$.
  </Step>
  <Step title="Average">
    Both unions are above 0, so both classes count: $(0.5 + 0.667)/2 = 0.5833$, the value the self-check expects.
  </Step>
</Steps>

<KeyIdea>

For each class: `p = pred == c`, `t = true == c`, intersection `(p & t).sum()`, union `(p | t).sum()`. Skip the class if the union is 0, otherwise keep `intersection / union`. Average what you kept. Masks plus sums implement almost any overlap metric.

</KeyIdea>

## The exam answer in PyTorch

Here is the complete answer, following the docstring's algorithm step by step, then the real output of the notebook's two self-check cells:

```python
def calculate_miou(pred_mask, true_mask, num_classes=2):
    pred_flat = pred_mask.reshape(-1)          # (B, H, W) -> (B*H*W,)
    true_flat = true_mask.reshape(-1)
    ious = []
    for cls in range(num_classes):             # loop over CLASSES only
        p = (pred_flat == cls)                 # bool tensor: predicted cls
        t = (true_flat == cls)                 # bool tensor: truly cls
        intersection = (p & t).sum().item()    # both say cls  (a Python int)
        union = (p | t).sum().item()           # either says cls
        if union == 0:                         # in neither map: skip, avoid 0/0
            continue
        ious.append(intersection / union)
    if len(ious) == 0:                         # no class to average over
        return 0.0
    return sum(ious) / len(ious)               # a Python float
```

```text
Calculated mIoU: 0.5833
Expected mIoU:   0.5833
✅ Metric Check Passed!
mIoU with missing class: 0.3750
Expected: Only class 0 IoU counted (should be 0.75)
❌ Missing class handling failed
```

The first check passes. The second one "fails", and that is not a bug in this function: the last section of this lesson shows that the cell itself is wrong. The docstring uses `.view(-1)` to flatten; `reshape(-1)` does the same job and also works on non-contiguous tensors (for example after a `transpose`), where `.view` raises an error.

<Mistake title="Five ways to lose the 10 marks">

- **Dividing before checking the union.** With tensors, `0 / 0` gives `tensor(nan)`, and one `nan` turns the whole mean into `nan`; after `.item()` the same division raises `ZeroDivisionError: division by zero`. Check `if union == 0` first.
- **Using `and` / `or` instead of `&` / `|`.** `p and t` asks Python for one True or False and fails with "Boolean value of Tensor with more than one value is ambiguous".
- **Looping over pixels or images** with nested `for` loops. It gives the right number slowly and breaks the task's explicit "vectorised operations only" rule.
- **Forgetting the empty list.** If every class is skipped, `sum([]) / len([])` is another `ZeroDivisionError`. Return `0.0` (the official solution's choice) when `ious` is empty.
- **Importing a ready-made metric** from `sklearn` or `torchmetrics`. Both are explicitly banned in this task, so the whole point of the part would be lost.

</Mistake>

## When a self-check disagrees with the specification

The notebook's extra cell, "Missing Class Handling", uses

$$
\text{pred} = \begin{bmatrix} 0 & 0 \\ 0 & 1 \end{bmatrix}, \qquad \text{true} = \begin{bmatrix} 0 & 0 \\ 0 & 0 \end{bmatrix}
$$

and expects **0.75**, with the comment "Class 1: Union = 0 (doesn't exist in target) → Should be skipped". Check that claim in 30 seconds by hand:

<Steps title="Re-computing the missing-class check">
  <Step title="Class 0">
    Predicted at 3 pixels, true at all 4: intersection 3, union 4, $\text{IoU}_0 = 0.75$.
  </Step>
  <Step title="Class 1">
    Predicted at 1 pixel (bottom right), true at none. Intersection 0, but union **1**, not 0. So the written rule does **not** skip it: $\text{IoU}_1 = 0/1 = 0$.
  </Step>
  <Step title="Average">
    $(0.75 + 0)/2 = 0.375$. The cell's 0.75 would need class 1 to be skipped, and its union is not 0.
  </Step>
</Steps>

So the comment is wrong: a class that is missing from the **target** but predicted somewhere has a union of 1 or more, and scoring it 0 is exactly right, because the model raised a false alarm. The notebook blurs the two ideas in one phrase, "If union == 0 (class doesn't exist in target), skip it". The value 0.75 comes from a different convention, averaging only classes present in the ground truth. Compare the conventions:

The audit settles it. The precise instruction ("Check if union == 0 BEFORE dividing", "If Union == 0 … skip this class") gives 0.375; the official solution uses that rule and also prints "Missing class handling failed"; and the grader's test (stored in the notebook's otter metadata, not shown in any cell), a class absent from **both** maps giving 1.0, passes under that rule. <Takeaways>

- $\text{IoU}_c = \dfrac{|P_c \cap T_c|}{|P_c \cup T_c|} = \dfrac{TP}{TP + FP + FN}$; mean IoU averages over the classes whose union is not 0.
- Code: flatten with `reshape(-1)`, loop over classes only, `p = pred == c`, `t = true == c`, `(p & t).sum().item()`, `(p | t).sum().item()`; `continue` when the union is 0; return `0.0` for an empty list, otherwise the average as a Python float.
- A class that is absent from the target but predicted has union ≥ 1 and correctly scores 0; only a class in **neither** map is skipped.
- The notebook's missing-class cell expects 0.75, but the written rule gives 0.375 (the official solution agrees). When a check contradicts the specification, verify by hand and follow the specification.

</Takeaways>
