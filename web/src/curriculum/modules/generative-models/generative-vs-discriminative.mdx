Most models in this course answer a question *about* an input: is this email spam, which digit is this, what will this flat sell for? Generative AI works the other way round. It produces brand-new inputs: a photo that was never taken, an essay nobody wrote, a voice that never spoke. You have already met one kind, the language models that write text; this module covers the rest. This lesson is about the one idea that separates the two kinds of model, and it is a favourite of NOAI papers: **what each model learns about the data**.

<Analogy title="The judge and the artist">

A judge at a photo competition can look at two Merlion pictures and tell you which one is real and which one is a fake. To do that, she only needs to spot the *differences* between real and fake photos. An artist who can paint a brand-new Merlion needs much more: the shape of the lion's head, the fish tail, the water spout, the Marina Bay skyline behind it, all in the right proportions. The judge is a **discriminative** model. The artist is a **generative** model.

</Analogy>

## Two different things to learn

Suppose each example has some features $x$ (the pixels of a photo, the words of an email) and a label $y$ (cat or dog, spam or not). Three probabilities appear in this lesson. The vertical bar $\mid$ is read "given".

- $P(y \mid x)$, read "the probability of $y$ given $x$", is a <Term def="The probability of one thing once you already know another. P(y | x) asks: among the examples with features x, what fraction have label y?">conditional probability</Term>: *I have already seen this email; how likely is it to be spam?*
- $P(x)$ is the probability of seeing the input $x$ at all: *how typical is an email like this one?* It describes how the data itself is spread out, its <Term def="A description of how likely every possible value is. For data, it tells you which inputs are common, which are rare and which never happen.">distribution</Term>.
- $P(x, y)$ is the <Term def="The probability that two things happen together, e.g. P(x, y) = the chance that an email contains these words AND is spam.">joint probability</Term> (the [probability rules](#/learn/probability-and-statistics/probability-rules) lesson wrote this as $P(A \cap B)$; the comma means the same "and"): *how likely is it to see an email like this that is also spam?*

A **discriminative model** learns only $P(y \mid x)$, or even just a boundary between the classes. A **generative model** learns how the data itself is distributed: $P(x)$ if there are no labels, or $P(x, y)$ if there are. The second is a much bigger job, and you can see why when you watch both kinds of model fit the same data.

<GenVsDiscToggle />

The discriminative model needs 3 numbers: two weights and a bias for its straight boundary. The generative model needs 11: for each class, the centre of its hill (2 numbers) and how far the hill spreads left-right, how far it spreads up-down, and its tilt (3 numbers for a 2-D bell curve), plus how common class A is (class B's share is then whatever is left). With those extra numbers it knows *where the data lives*, so it can do something the boundary cannot: **press Sample and it makes new points**.

## A worked example you can do by hand

Here are 100 emails, counted by whether they contain the word "free" ($x$) and whether they are spam ($y$). A table of counts like this *is* a generative model of the data: it describes the full joint distribution $P(x, y)$.

| | spam | not spam | row total |
|---|---|---|---|
| contains "free" | 18 | 2 | 20 |
| no "free" | 12 | 68 | 80 |
| column total | 30 | 70 | 100 |

<Steps title="Everything follows from the joint table">
  <Step title="Joint: $P(\text{free}, \text{spam})$">
    Read one cell: 18 of the 100 emails contain "free" and are spam, so $P(\text{free}, \text{spam}) = 18/100 = 0.18$.
  </Step>
  <Step title="Marginal: $P(\text{free})$">
    Add along the row: $(18 + 2)/100 = 0.20$. This says how common the input is, which a pure classifier never knows.
  </Step>
  <Step title="Conditional: $P(\text{spam} \mid \text{free})$">
    Look only at the "free" row: 18 of its 20 emails are spam, so $P(\text{spam} \mid \text{free}) = 18/20 = 0.9$. In symbols, $P(y \mid x) = P(x, y)/P(x) = 0.18/0.20 = 0.9$.
  </Step>
  <Step title="The same answer with Bayes' rule (Bayes' theorem)">
    A generative model is often stored as $P(y)$ and $P(x \mid y)$ instead. Here $P(\text{spam}) = 30/100 = 0.3$ and $P(\text{free} \mid \text{spam}) = 18/30 = 0.6$, so Bayes' rule, the [Bayes' theorem](#/learn/probability-and-statistics/bayes-theorem) you already know (written out below), gives $\dfrac{0.6 \times 0.3}{0.2} = \dfrac{0.18}{0.2} = 0.9$ again.
  </Step>
  <Step title="Now try going backwards">
    A discriminative model stores only $P(\text{spam} \mid \text{free}) = 0.9$ and $P(\text{spam} \mid \text{no free}) = 12/80 = 0.15$. From these two numbers you **cannot** recover the table. A different inbox with counts 54, 6, 6 and 34 (so 60 emails contain "free", not 20) gives exactly the same two numbers: $54/60 = 0.9$ and $6/40 = 0.15$. The information about the inputs is simply not there.
  </Step>
</Steps>

The pattern behind the steps is worth writing down once:

$$
P(x, y) = P(x \mid y)\,P(y)
$$

$$
P(y \mid x) = \frac{P(x \mid y)\,P(y)}{P(x)}
$$

$$
P(x) = \sum_{y'} P(x \mid y')\,P(y')
$$

- $P(y)$ is the <Term def="How common each class is before you look at the features, e.g. 30% of all emails are spam.">prior</Term>: the share of each class.
- $P(x \mid y)$ describes what the inputs of class $y$ look like: one "hill" per class.
- $P(x)$ adds up the hills of all classes ($y'$ runs over every class), so it says how typical $x$ is overall.

So the generative direction contains the discriminative one: from $P(x \mid y)$ and $P(y)$, Bayes' rule hands you a classifier for free. (For continuous features such as heights or pixel brightness, we write a lowercase $p$ for a <Term def="For continuous values, the height of the probability curve at a point. Higher means values near that point are more likely; the area under the curve is 1.">probability density</Term>. The rules are the same.)

<KeyIdea>

A **discriminative** model learns $P(y \mid x)$: just enough to separate the classes. A **generative** model learns how the data is distributed, $P(x)$ or $P(x, y) = P(x \mid y)\,P(y)$. That is harder, but it can also **classify** (with Bayes' rule), **score how typical an input is** ($P(x)$), and **create new examples** (by sampling).

</KeyIdea>

## What "sampling" means

To <Term def="To draw a random value from a probability distribution, so that common values come up often and rare values rarely.">sample</Term> from a distribution means to draw a random value from it, so that likely values come up often and unlikely values rarely. Rolling a fair die samples from the distribution "1 to 6, each with probability 1/6".

Sampling from the email table works the same way. Pick one of the four cells at random, with chances 18%, 2%, 12% and 68%. Or do it in two stages, exactly like the Sample button in the first figure:

1. pick a class with probability $P(y)$: spam 30% of the time, not spam 70%;
2. then pick the features from that class's distribution $P(x \mid y)$: for a spam email, "contains free" with probability 0.6.

The result is a new (features, label) pair that follows the same pattern as the real data. A discriminative model has nothing to sample from: it can only answer questions about an $x$ that you give it.

Real images are far harder. A small 64 × 64 colour image is $64 \times 64 \times 3 = 12{,}288$ numbers, and nearly every combination of those numbers looks like TV static. Real photos occupy a tiny, oddly shaped corner of that space, and $P(x)$ must describe exactly where that corner is. You cannot write such a distribution down as a table or a single bell curve. Modern generators use a trick instead: they start from simple random numbers, called <Term def="Random numbers, usually drawn from a standard normal distribution, that a generator turns into an output. Different noise gives a different output.">noise</Term> $z$, drawn from a standard normal distribution, and a trained neural network $G$ turns them into an example:

$$
z \sim \mathcal N(0, I), \qquad x_{\text{new}} = G(z)
$$

Read $z \sim \mathcal N(0, I)$ as "$z$ is a list of random numbers, each drawn from the bell curve with mean 0 and standard deviation 1, independently". All the knowledge about the data is in the weights of $G$, which training adjusts until the outputs look like real data. Every new $z$ gives a new example.

<Analogy title="A kaya toast machine">

Imagine a machine that has learned what kaya toast looks like. It has four dials (toastiness, how far the kaya spreads, the size of the butter slab, how domed the loaf is) and a random-number generator that sets the dials. Every press gives a slightly different but believable slice. The machine never copies a photo of a slice it has seen: it has learned the *pattern* of kaya toast and makes endless new ones.

</Analogy>

<NoiseToSample />

Two things to notice. First, small changes to $z$ give small changes to the output, so the space of noise vectors is laid out smoothly. Second, the same seed always gives the same noise and therefore the same toast. That is why image generators such as Stable Diffusion let you type in a seed: reusing it with the same prompt and settings reproduces an image exactly.

<KeyIdea>

**Generating = sampling.** A generative model turns simple random noise into data through learned transformations, so every random draw gives a new, realistic example, and the same seed reproduces the same example.

</KeyIdea>

## Conditional generation: the arrow turned round

Most useful generators take an input too. A text-to-image model is asked for "a cat sleeping on an MRT seat", not for any random image. It models $P(\text{image} \mid \text{prompt})$. Compare the arrows:

- classifier: image $\rightarrow$ label, modelling $P(y \mid x)$;
- conditional generator: label or prompt $\rightarrow$ image, modelling $P(x \mid y)$.

Both are conditional probabilities, but they point in opposite directions. The generator must produce the many numbers of an image, while the classifier only produces a few numbers (one probability per label).

<Mistake title="“GPT predicts a probability given the previous words, so it must be discriminative”">

GPT does learn a conditional, $P(\text{next token} \mid \text{tokens so far})$. But the "label" it predicts is part of the data itself, the next piece of the text. Multiplying these conditionals together gives the probability of a whole text $x_1, x_2, \dots, x_n$:

$$
\begin{aligned}
P(x_1, \dots, x_n) = {} & P(x_1)\,P(x_2 \mid x_1) \\
& \cdots P(x_n \mid x_1, \dots, x_{n-1})
\end{aligned}
$$

That is a model of $P(\text{text})$. Sampling one token at a time writes new text. Models that build $P(x)$ one piece at a time like this are called <Term def="Models that generate data one piece at a time, each piece conditioned on all the pieces before it (e.g. GPT writing token after token).">autoregressive</Term>, and they are generative.

</Mistake>

## Why not always use a generative model?

If a generative model can do everything a discriminative one can and more, why bother with discriminative models at all?

- **Effort.** Modelling every detail of the inputs is a much larger task than drawing a boundary. If all you need is a label, a discriminative model puts all its capacity and data into exactly that.
- **Accuracy.** With plenty of labelled data, a discriminative classifier usually classifies at least as well. A generative classifier is only as good as its picture of the data, and a wrong assumption (such as [Naive Bayes](#/learn/classification/naive-bayes)'s "words are independent once you know the class") can mislead its Bayes'-rule answer.
- **But generative wins** when you need new data (images, text, music, synthetic training examples), when you want to know whether an input is unusual (low $P(x)$, as in the second figure), or when you have little labelled data and the shape of the inputs helps.

## The generative family tree

You met autoregressive models in the [decoding lesson](#/learn/large-language-models/decoding-and-sampling); the rest of this module covers VAEs, GANs and diffusion models. Each family has a different answer to the question "how do we turn simple randomness into realistic data?"

| Family | How it generates | Famous examples |
|---|---|---|
| Classical class models | sample $y$ from $P(y)$, then $x$ from $P(x \mid y)$ | Naive Bayes, Gaussian class models |
| Autoregressive models | one token or pixel at a time, each conditioned on the ones before | GPT, other large language models |
| Variational autoencoders (VAEs) | decode a random point of a smooth "latent" space | VAE; the image compressor inside Stable Diffusion |
| Generative adversarial networks (GANs) | one pass of a generator trained against a real-or-fake judge | StyleGAN (photo-realistic faces) |
| Diffusion models | start from pure noise and remove a little noise at a time | Stable Diffusion, DALL·E 2 and 3, Imagen |

## In code

Here is the contrast in scikit-learn on a 2-D dataset like the one in the first figure. `LogisticRegression` is discriminative. `GaussianNB` (Gaussian Naive Bayes) is generative: it stores a mean and a variance for each feature in each class, plus the class shares. Both can classify, but only the generative one has what it takes to invent new points.

<PyRunner packages={['numpy', 'scikit-learn']} code={`import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.naive_bayes import GaussianNB

rng = np.random.default_rng(0)
# 50 points of class A (label 0) and 50 of class B (label 1)
A = rng.normal(loc=[3, 4], scale=0.8, size=(50, 2))
B = rng.normal(loc=[7, 2], scale=0.8, size=(50, 2))
X = np.vstack([A, B])
y = np.array([0] * 50 + [1] * 50)

disc = LogisticRegression().fit(X, y)   # learns P(y | x)
gen = GaussianNB().fit(X, y)            # learns P(x | y), P(y)

x_new = [[5.0, 3.0]]
print("P(B | x), discriminative:", disc.predict_proba(x_new)[0, 1].round(3))
print("P(B | x), generative:    ", gen.predict_proba(x_new)[0, 1].round(3))
print("disc stores w and b:   ", disc.coef_.round(2), disc.intercept_.round(2))
print("gen stores class means:", gen.theta_.round(2).tolist())
print("gen stores variances:  ", gen.var_.round(2).tolist())
print("gen stores P(y):       ", gen.class_prior_)

# Only the generative model can make new data.
# 1. pick a class with probability P(y)
k = rng.choice(2, size=5, p=gen.class_prior_)
# 2. draw x from that class's bell curves
new_x = rng.normal(gen.theta_[k], np.sqrt(gen.var_[k]))
for label, point in zip(k, new_x.round(2)):
    print("new point", point, "from class", "AB"[label])`} />

Both models say the point $(5, 3)$, halfway between the classes, is more likely B, but they give different probabilities (about 0.58 and 0.74) because they reach $P(y \mid x)$ by different routes. The last few lines are the two-stage sampling recipe from earlier, written in NumPy. `LogisticRegression` keeps only `coef_` and `intercept_`, so there is no such recipe for it.

<Takeaways>

- A **discriminative** model learns $P(y \mid x)$, or just a boundary: logistic regression, SVMs, decision trees, image classifiers.
- A **generative** model learns the data distribution, $P(x)$ or $P(x, y) = P(x \mid y)\,P(y)$. It can classify with Bayes' rule, score how typical an input is, and **sample** new data.
- From the joint table you can compute $P(y \mid x)$, but from $P(y \mid x)$ alone you can never recover $P(x)$.
- Modern generators sample by turning random noise $z$ into data, $x = G(z)$; the same seed gives the same output, and a conditional generator models $P(x \mid \text{prompt})$.
- Families: autoregressive models (GPT), VAEs, GANs and diffusion models (Stable Diffusion).

</Takeaways>
