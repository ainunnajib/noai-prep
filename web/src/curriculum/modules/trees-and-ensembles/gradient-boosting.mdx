AdaBoost improved a team of stumps by **re-weighting** the examples it got wrong. Gradient boosting takes a more direct route: every new tree is trained to **predict the mistakes** of the model so far, and is then added to it. This idea (Jerome Friedman, 2001) powers XGBoost, LightGBM and CatBoost, the libraries that win most competitions on tables of data. It was also Task 1 of the **NOAI 2026 Final**: implement gradient boosting from scratch in NumPy. By the end of this lesson you will be able to write every line of it.

<Analogy title="Sculpting">

A sculptor does not carve a statue in one cut. She first roughs out the overall shape, then looks at what is still wrong (the nose is too big, the shoulder too flat) and shaves off a little of exactly that. Many careful passes add up to a fine statue. Gradient boosting builds a model the same way: a rough first guess, then a long series of small corrections, each aimed at whatever is still wrong.

</Analogy>

## Fitting what is left over

Take a <Term def="A task where the model predicts a number, such as a price or a temperature, rather than a class.">regression</Term> problem: from an input $x$, predict a number $y$. Gradient boosting builds its prediction $F(x)$ in rounds.

1. **Start with a constant**: predict the same number $F_0$ for everyone, the mean of the training targets.
2. **Measure what is left over.** For every training example, the <Term def="The gap between the true value and the prediction, y − F(x). Positive when the model predicts too low, negative when it predicts too high.">residual</Term> $r_i = y_i - F(x_i)$ is how far the prediction is from the truth.
3. **Fit a small tree to the residuals.** A shallow regression tree $h(x)$ learns to predict the residual from $x$: a positive correction where the model is too low, a negative one where it is too high.
4. **Add a fraction of that tree** to the model, then go back to step 2 with the new residuals.

The stepper below does this on 40 noisy training points. The orange steps in the residual panel are the trees; watch the residuals they chase shrink round by round.

<GBResidualStepper />

In symbols, round $m$ updates the model like this:

$$
F_m(x) = F_{m-1}(x) + \eta \, h_m(x)
$$

- $F_{m-1}(x)$ is the model after $m - 1$ trees, and $F_m(x)$ the model after $m$ trees;
- $h_m(x)$ is tree number $m$, fitted to the residuals $y_i - F_{m-1}(x_i)$;
- $\eta$ (eta) is the <Term def="A number between 0 and 1 that scales each tree's output before it is added to the model. Smaller values mean smaller, more careful steps and need more trees. Also called shrinkage.">learning rate</Term>, also called **shrinkage**, usually between 0.01 and 0.3.

So the final model is the starting constant plus a scaled sum of all the trees, $F_M(x) = F_0 + \eta \sum_{m=1}^{M} h_m(x)$, and that is also how you predict for a new $x$.

<Steps title="Two rounds by hand">
  <Step title="Start with the mean">
    Data: $x = [1, 2, 3, 4]$ and $y = [3, 1, 2, 10]$; stumps (depth-1 trees) and $\eta = 0.1$. The mean is $F_0 = \tfrac{3 + 1 + 2 + 10}{4} = 4$ for every example. MSE $= \tfrac{1 + 9 + 4 + 36}{4} = 12.5$.
  </Step>
  <Step title="Residuals">
    $r = y - F_0 = [-1, -3, -2, 6]$. Three examples are over-predicted, one is badly under-predicted.
  </Step>
  <Step title="Tree 1 learns the residuals">
    The best single split is $x \le 3.5$. A regression tree's leaf predicts the **mean** of its targets: left leaf $\tfrac{-1 - 3 - 2}{3} = -2$, right leaf $6$.
  </Step>
  <Step title="Take a small step">
    $F_1 = F_0 + 0.1 \times h_1 = [4 - 0.2,\ 4 - 0.2,\ 4 - 0.2,\ 4 + 0.6] = [3.8, 3.8, 3.8, 4.6]$. The new residuals are $[-0.8, -2.8, -1.8, 5.4]$, so MSE $= \tfrac{0.64 + 7.84 + 3.24 + 29.16}{4} = 10.22$.
  </Step>
  <Step title="Repeat">
    Tree 2 makes the same split, with leaves $-1.8$ and $5.4$, giving $F_2 = [3.62, 3.62, 3.62, 5.14]$ and MSE $\approx 8.37$. After 100 stumps the predictions are $[2.88, 1.24, 1.98, 9.90]$: close to $y$, built from 100 small corrections.
  </Step>
</Steps>

## Why "gradient"? Pseudo-residuals

The gradient is hiding in the residuals. Measure the error on one example with the <Term def="The squared-error loss for one example, ½(y − F)². The ½ is there so that its derivative comes out neatly as −(y − F).">L2 loss</Term> $L = \frac12 (y - F)^2$, where $F$ is the current prediction. Its derivative with respect to the prediction is (chain rule: bring down the 2, times the derivative of the inside, which is $-1$)

$$
\frac{\partial L}{\partial F} = \tfrac12 \times 2 (y - F) \times (-1) = -(y - F).
$$

Gradient descent says: to make the loss smaller, nudge $F$ in the direction of the **negative** gradient, $-\frac{\partial L}{\partial F} = y - F$. That is exactly the residual! So "add a little of the residual to each prediction" is one step of gradient descent on the predictions.

Nudging each training prediction directly (the 40 points in the stepper, say) would only memorise the training set and say nothing about a new $x$. So gradient boosting fits a **tree** to the negative gradients: the tree learns *which way to move* as a function of $x$, which also works for inputs it has never seen. The tree's targets are called <Term def="The negative gradient of the loss with respect to the current prediction, −∂L/∂F, for each training example. Each new tree in gradient boosting is fitted to them. For squared error they are the ordinary residuals.">pseudo-residuals</Term>, because for other losses they are no longer ordinary residuals.

The recipe now works for **any** loss you can differentiate (AdaBoost is close to this recipe applied to the exponential loss). The other loss NOAI asks about is the <Term def="The absolute-error loss for one example, |y − F|. It grows in a straight line with the size of the error, so a single huge error matters far less than under squared error.">L1 loss</Term> $L = |y - F|$. If the model predicts too low ($y > F$), then $L = y - F$ and the slope with respect to $F$ is $-1$; if it predicts too high, the slope is $+1$. So the negative gradient is $+1$ or $-1$:

$$
-\frac{\partial L}{\partial F} = \operatorname{sign}(y - F)
$$

Each example only says "go up" or "go down", however big its error is. (Exactly at $y = F$ the slope is undefined; `np.sign` returns 0 there, which is a fine choice.)

Each loss also has its own best **starting constant**, the single number that makes the total training loss smallest: the **mean** of $y$ for L2 and the **median** for L1 (the middle value once the targets are sorted; with an even number of targets any value between the two middle ones is equally good, and `np.median` takes their average).

| Loss | $L(y, F)$ | pseudo-residual | start $F_0$ |
|---|---|---|---|
| L2 (squared error) | ${\frac12 (y - F)^2}$ | ${y - F}$ | mean |
| L1 (absolute error) | ${\lvert y - F \rvert}$ | ${\operatorname{sign}(y - F)}$ | median |

On $y = [3, 1, 2, 10]$, the mean 4 gives an MSE of 12.5 (the median 2.5 gives 14.75), while the median gives a mean absolute error of 2.5 (the mean gives 3). Each loss prefers its own constant. Now add an outlier:

<KeyIdea>

Every tree in gradient boosting is fitted to the **negative gradient of the loss** with respect to the current predictions. For L2 that is the residual $y - F$ (start from the mean); for L1 it is $\operatorname{sign}(y - F)$ (start from the median), which makes L1 boosting **robust to outliers**.

</KeyIdea>

<Note title="Boosting for classification">

For a yes/no target ($y = 0$ or $1$), the running total $F(x)$ is a score (the log-odds), and the predicted probability is $p = \sigma(F)$, the sigmoid from [logistic regression](#/learn/classification/logistic-regression). With the log-loss, the negative gradient with respect to $F$ is simply $y - p$: each tree is fitted to **"true label minus predicted probability"**, starting from the log-odds of the class rate. For example, a positive example ($y = 1$) that the model gives $p = 0.8$ has pseudo-residual $1 - 0.8 = 0.2$. This is what `GradientBoostingClassifier` and `XGBClassifier` do.

</Note>

<Mistake>

The classic slips when coding this:

- **Sign flipped**: `y_pred - y` is the gradient, not the *negative* gradient. Every tree then pushes the predictions the wrong way and the loss goes **up**.
- **Learning rate forgotten in `predict`**: if `fit` adds `lr * tree.predict(X)`, `predict` must too. Training and prediction must replay exactly the same steps.
- **Residuals from the start every round**: the pseudo-residuals must use the **current** predictions $F_{m-1}$, not $F_0$; otherwise every tree learns the same thing.
- **Fitting the tree to `y`** instead of to the pseudo-residuals.

</Mistake>

## Shrinkage, the number of trees, and early stopping

The learning rate and the number of trees work as a pair. A smaller $\eta$ takes smaller steps, so you need **more trees** to reach the same training loss. In return, the model usually **generalises better**: many small corrections average out noise that one big correction would have copied. That is why small learning rates (0.01 to 0.1) with hundreds or thousands of trees are standard.

Adding trees keeps lowering the **training** loss, but after a point each new tree mostly fits noise and the **validation** loss creeps back up. So let the validation data choose the number of trees. <Term def="Stopping training once the validation loss has stopped improving, and keeping the model from the best point. In boosting it chooses the number of trees.">Early stopping</Term> works like this:

1. After each new tree, compute the loss on a **validation set** (data the trees never train on), updating its predictions with the same tree and the same step.
2. If the validation loss beats the best so far (by more than a tiny `min_delta`), remember it and the number of trees, and reset a counter to 0.
3. Otherwise add 1 to the counter. When the counter reaches the <Term def="How many rounds in a row early stopping waits without any improvement in the validation loss before it gives up.">patience</Term>, stop.
4. Keep only the trees up to the best round.

<PatienceTracker />

<KeyIdea>

**Smaller $\eta$ means more trees but usually a better model.** **Early stopping** tracks the validation loss after every tree, stops once it has not improved for `patience` rounds, and keeps the best number of trees.

</KeyIdea>

## XGBoost, LightGBM and CatBoost

Three famous libraries run the same loop, faster and with extra protection against overfitting:

- <Term def="eXtreme Gradient Boosting (2014): a fast gradient boosting library with regularisation of the leaf values, second-order (Newton) steps and built-in handling of missing values.">XGBoost</Term> penalises large leaf values and many leaves (**regularisation**), uses the second derivative of the loss to choose leaf values, and learns a **default direction for missing values** at every split, so you do not need to fill them in.
- <Term def="Light Gradient Boosting Machine (Microsoft, 2017): gradient boosting that bins feature values into histograms for very fast split search and grows trees leaf by leaf.">LightGBM</Term> sorts feature values into a few hundred **histogram bins**, which makes finding splits very fast on big data. scikit-learn's `HistGradientBoostingRegressor` copies this design and also handles missing values natively.
- <Term def="Categorical Boosting (Yandex, 2017): gradient boosting with careful built-in handling of categorical features such as town or flat type.">CatBoost</Term> handles **categorical** features (such as town or flat type) directly, without you turning them into numbers first.

<PastPaperQuestion paper="prelim2026" n={259} />

Here is scikit-learn's LightGBM-style booster on a table where a fifth of all the values are missing. It trains anyway, while a linear model refuses:

```python
import numpy as np
from sklearn.datasets import make_friedman1
from sklearn.model_selection import train_test_split
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.linear_model import LinearRegression

X, y = make_friedman1(n_samples=2000, noise=1.0, random_state=0)
X[np.random.default_rng(0).random(X.shape) < 0.2] = np.nan   # knock out 20% of all values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=0)

model = HistGradientBoostingRegressor(max_iter=500, early_stopping=True, random_state=0)
model.fit(X_tr, y_tr)                        # no imputation needed
print("boosting rounds run before early stopping:", model.n_iter_)
print("test R^2 with 20% of values missing:", round(model.score(X_te, y_te), 3))
try:
    LinearRegression().fit(X_tr, y_tr)
except ValueError as e:
    print("LinearRegression refuses:", str(e).split(".")[0])
```

<Takeaways>

- Gradient boosting starts from a constant and adds small trees **in sequence**: $F_m = F_{m-1} + \eta \, h_m$, each tree fitted to what the model still gets wrong.
- The tree targets are **pseudo-residuals**, the negative gradient of the loss: $y - F$ for L2 (start from the mean) and $\operatorname{sign}(y - F)$ for L1 (start from the median, robust to outliers).
- A smaller **learning rate** needs more trees but usually generalises better; **early stopping** keeps the best number of trees.
- **XGBoost, LightGBM and CatBoost** are fast, regularised gradient boosting with native missing-value handling: the model to beat on tables of data.

</Takeaways>
