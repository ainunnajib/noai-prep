AI code is full of loops: over <Term def="One full pass of training through the whole training set.">epochs</Term>, over <Term def="A small group of training examples that a model processes together in one step.">batches</Term>, over pairs of inputs and labels. Python has four tools that make these loops shorter, clearer and lighter on memory: **list comprehensions**, **zip**, **enumerate** and **generators**. NOAI questions love asking what one line of them prints, so this lesson teaches you to read each one like a machine.

## List comprehensions: a loop in one line

<Analogy title="A juice stall's conveyor belt">

Fruit rides along a belt. An inspector removes the bruised ones, the rest are juiced, and the cups come out at the end in the same order the fruit went in. A list comprehension is that belt: values go in, a test removes some, an expression transforms the rest, and the results come out in order.

</Analogy>

A <Term def="A one-line way to build a list from another sequence: [expression for item in iterable if condition].">list comprehension</Term> builds a new list from an existing sequence:

$$
[\;\underbrace{\texttt{x ** 2}}_{\text{expression}}\;\;\underbrace{\texttt{for x in nums}}_{\text{loop}}\;\;\underbrace{\texttt{if x > 0}}_{\text{filter (optional)}}\;]
$$

Read it as: "**x squared, for each x in nums, keeping only the x that are greater than 0**". The loop part says where the values come from, the filter decides which ones are kept, and the expression says what to put in the new list. It does exactly the same as this loop:

```python
result = []
for x in nums:
    if x > 0:
        result.append(x ** 2)
```

<ComprehensionMachine />

<KeyIdea>

`[expression for x in items if condition]` means: for each `x` in `items`, in order, check the condition; if it is true, work out the expression and append it. It is a for loop with `append`, written in one line.

</KeyIdea>

<Steps title="Work out [w.upper() for w in words if len(w) > 3]">
  <Step title="Set up">
    `words = ['kopi', 'teh', 'milo', 'bandung']`. The filter keeps words longer than 3 letters, and the expression turns each kept word into capitals.
  </Step>
  <Step title="'kopi'">
    `len('kopi')` is 4, and $4 > 3$, so it is kept: append `'KOPI'`.
  </Step>
  <Step title="'teh'">
    `len('teh')` is 3, and $3 > 3$ is False, so `'teh'` is skipped. Nothing is appended.
  </Step>
  <Step title="'milo' and 'bandung'">
    Lengths 4 and 7 both pass, so append `'MILO'` and then `'BANDUNG'`.
  </Step>
  <Step title="Result">
    `['KOPI', 'MILO', 'BANDUNG']`: three items, in their original order.
  </Step>
</Steps>

Two more forms you will meet:

- **An if-else inside the expression** changes values instead of removing them. `[x if x > 0 else 0 for x in nums]` turns every negative number into 0 and keeps the list the same length. That is the <Term def="Rectified linear unit: the function that keeps positive numbers and turns negative numbers into 0. Neural networks use it everywhere.">ReLU</Term> function from neural networks, written in one line.
- **Dict and set comprehensions** use curly braces: `{w: len(w) for w in words}` builds a dict, and `{x % 3 for x in nums}` builds a set.

<PyRunner code={compCode} />

<Mistake title="Putting the if-else in the wrong place">

A filter `if` goes at the **end** and has no `else`: `[x for x in nums if x > 0]`. A choice between two values goes at the **front** as `a if condition else b`: `[x if x > 0 else 0 for x in nums]`. Writing `[x for x in nums if x > 0 else 0]` is a `SyntaxError`.

</Mistake>

### Two `for` clauses

A comprehension can have more than one `for`. Read the `for` clauses **left to right as nested loops, outer loop first**:

```python
pairs = [(i, j) for i in range(2) for j in range(3)]

# exactly the same as:
pairs = []
for i in range(2):          # first for = outer loop
    for j in range(3):      # second for = inner loop
        pairs.append((i, j))
print(pairs)
```

```text
[(0, 0), (0, 1), (0, 2), (1, 0), (1, 1), (1, 2)]
```

`j` changes fastest because it belongs to the inner loop. The same pattern flattens a list of lists: `[x for row in M for x in row]` turns `[[1, 2], [3], [4, 5]]` into `[1, 2, 3, 4, 5]`.

Don't confuse this with a comprehension **inside** another comprehension. The inner brackets build a whole list for each value of the outer loop, so the result is a list of lists. Careful: here the outer loop is the `for` written **last**, outside the inner brackets.

```python
print([[i * j for j in range(3)] for i in range(2)])
```

```text
[[0, 0, 0], [0, 1, 2]]
```

## zip and enumerate: looping over pairs

<Analogy title="The zip on your jacket">

When you pull a zip up, a tooth from the left side locks into a tooth from the right side, one pair at a time. If one side were shorter, the zip would simply stop where that side ends.

</Analogy>

`zip(a, b)` pairs up items at the same position into tuples: the first with the first, the second with the second, and so on. It **stops at the end of the shorter list**, silently dropping any leftovers. `enumerate(items)` pairs each item with a counter that starts at 0 (or at any number you give with `start=`):

```python
names = ['Aisha', 'Ben', 'Chen']
scores = [78, 92, 85]

for name, score in zip(names, scores):   # unpack each tuple into two names
    print(name, score)

for i, name in enumerate(names, start=1):
    print(i, name)
```

```text
Aisha 78
Ben 92
Chen 85
1 Aisha
2 Ben
3 Chen
```

Both return an <Term def="An object that hands out the items of a sequence one at a time when asked (by next() or a for loop). Once it has handed out everything, it is empty.">iterator</Term>, not a list. An iterator hands out its items one at a time and is then **used up**: you can loop over it only once. Printing it directly shows only something like `<zip object at 0x7f…>` (the number is a memory address and changes every run). Wrap it in `list()` to see every pair at once.

<ZipZipper />

Two patterns worth memorising:

- `dict(zip(keys, values))` builds a dictionary from two lists: `dict(zip(names, scores))` gives `{'Aisha': 78, 'Ben': 92, 'Chen': 85}`.
- `for i, x in enumerate(items):` replaces `for i in range(len(items)):` followed by `x = items[i]`. It is shorter and can't go out of range. PyTorch training loops use it to number batches: `for i, (inputs, labels) in enumerate(loader):`.

## Generators: values on demand

So far every list has been built **all at once**. A list of a million squares holds a million numbers in memory before you use the first one. Often you only need one value at a time: to add them up, or to feed one batch at a time to a model.

<Analogy title="The queue-number machine at a polyclinic">

The machine does not print all 500 numbers when the clinic opens. It prints the next number only when the next patient presses the button, and it only has to remember which number comes next.

</Analogy>

A <Term def="An iterator that produces its values one at a time, only when asked, instead of storing them all. Made with a generator expression (…) or a function that uses yield.">generator</Term> works like that. Its values are produced by <Term def="Working something out only at the moment it is needed, instead of in advance.">lazy evaluation</Term>: only when they are asked for. The simplest way to make one is a **generator expression**, which looks like a list comprehension in round brackets:

```python
squares_list = [x * x for x in range(1_000_000)]  # all values computed now
squares_gen = (x * x for x in range(1_000_000))   # nothing computed yet
```

(The underscores in `1_000_000` are just for readability, like the commas in 1,000,000.)

<GeneratorVsList />

The second way is a **generator function**: a function that uses `yield` instead of `return`. Calling it doesn't run its body. It returns a generator object, and each `next()` runs the body until the next `yield`, hands back that value, and **pauses** there, remembering all its local variables. When the body finishes, `next()` raises `StopIteration`.

<YieldStepper />

<KeyIdea>

A list stores all its values at once. A generator stores only its current position and computes the next value when asked, so its memory stays tiny however many values it will produce. In exchange, it can be read only once and in order: no indexing, no `len()`, no second pass.

</KeyIdea>

A `for` loop calls `next()` for you and stops quietly at `StopIteration`, which is why you can loop over a generator just like a list. Functions that consume a sequence also accept one: `sum(x * x for x in range(10))` adds up $0 + 1 + 4 + \dots + 81 = 285$ without ever building a list. A PyTorch <Term def="A PyTorch object that hands a training loop one batch of data at a time, loading each batch only when it is needed.">DataLoader</Term> works on the same lazy principle: each epoch's `for` loop gets a fresh iterator that loads one batch at a time, so a dataset far bigger than memory can stream through. Unlike a used-up generator, a DataLoader can be looped over again every epoch.

Measure the difference yourself. `sys.getsizeof` counts only the list object itself, which holds a million references; the million integer objects they point to take about 32 MB more, which the figure above includes. On a normal 64-bit computer the list object is about 8.4 MB and the generator 200 bytes. The Python in your browser is 32-bit, so it reports about half of each: roughly 4.2 MB and about 100 bytes. Either way, the third line shows the list is tens of thousands of times bigger.

A generator, a `zip` and an `enumerate` are all used up after one pass. The second pass gets nothing, with no error message. Run this: it prints `3 0`.

</Mistake>

<ExamTip>

Square brackets build a list now; round brackets around `x for x in …` build a **generator**, not a tuple. `yield` makes a function a generator function. `zip` stops at the shortest input and, like `enumerate`, returns an iterator: `print(zip(…))` shows `<zip object …>`, not the pairs. When tracing a comprehension, check the `range()` limits first; most wrong options come from starting at 1 or including the stop value.

</ExamTip>

<Takeaways>

- `[expr for x in items if cond]` is a for loop with `append`: filter first, then transform, keeping the original order. With two `for` clauses, the first one is the outer loop.
- `zip(a, b)` pairs items by position and stops at the shorter input; `enumerate(items)` pairs each item with its index.
- `zip`, `enumerate` and generators are iterators: lazy, one pass only. Use `list(...)` to see or keep their values.
- A generator (`(…)` or a function with `yield`) makes values on demand, so it uses almost no memory however long it runs.

</Takeaways>
