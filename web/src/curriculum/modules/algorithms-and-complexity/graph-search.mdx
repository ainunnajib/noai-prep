graph = {
    "Home": ["MRT", "Park"],
    "MRT": ["Home", "School", "Mall"],
    "Park": ["Home", "Mall", "Hawker"],
    "School": ["MRT", "Library"],

    "Clinic": ["Mall", "Hawker", "Pool", "Stadium"],
    "Pool": ["Library", "Clinic", "Stadium"],
    "Stadium": ["Clinic", "Pool"],
}

def bfs_path(graph, start, goal):
    queue = deque([start])
    parent = {start: None}
    while queue:
        # take the oldest place
        u = queue.popleft()
        if u == goal:
            break
        for v in graph[u]:
            # not seen yet
            if v not in parent:
                parent[v] = u
                queue.append(v)
    # walk back through the parents
    path, node = [], goal
    while node is not None:
        path.append(node)
        node = parent[node]
    return path[::-1]

def dfs_path(graph, start, goal):
    # each entry: (place, came from)
    stack = [(start, None)]
    parent = {}
    while stack:
        # take the newest place
        u, p = stack.pop()
        # an old copy: already visited
        if u in parent:
            # continue: skip the rest of this pass
            # and go straight to the next one
            continue
        # mark it when popped
        parent[u] = p
        if u == goal:
            break
        # reversed(...) walks the neighbour
        # list backwards
        for v in reversed(graph[u]):
            if v not in parent:
                stack.append((v, u))
    # walk back through the parents
    path, node = [], goal
    while node is not None:
        path.append(node)
        node = parent[node]
    return path[::-1]

In [Recursion and dynamic programming](#/learn/algorithms-and-complexity/recursion-and-dynamic-programming) you broke problems into smaller copies of themselves and remembered each answer. This lesson explores a different kind of structure: a **network** of connected things, such as MRT stations, friends on a chat app or pages on the web. Exploring a network is called **graph search**, and there are two classic ways to do it: **breadth-first** (everything near before anything far) and **depth-first** (one route as far as it goes, then back up). They sit underneath route planners, web crawlers and puzzle solvers; AI uses the same ideas, from backpropagation to the way a chatbot picks its next words; and NOAI asks you to trace both searches by hand.

## Graphs: nodes, edges and adjacency lists

A <Term def="A set of nodes (also called vertices) joined by edges. Maps, social networks, the web and neural network computations are all graphs.">graph</Term> is a set of **nodes** (places, people, web pages) joined by **edges** (paths, friendships, links). Two nodes joined by an edge are **neighbours**. In Python a graph is usually stored as an <Term def="A dict mapping each node to the list of its neighbours.">adjacency list</Term>: a dict from each node to the list of its neighbours.

Here is part of the map you will search in this lesson, stored as an adjacency list:

```python
graph = {
    "Home": ["MRT", "Park"],
    "MRT": ["Home", "School", "Mall"],
    "Park": ["Home", "Mall", "Hawker"],
    # ... one entry per place
}
print(graph["MRT"])
# ['Home', 'School', 'Mall']
```

The paths on this map go both ways (an **undirected** graph), so every edge is written twice: MRT is in Home's list and Home is in MRT's. Finding a node's neighbours is a single dict lookup.

## Breadth-first and depth-first search

<Analogy title="Searching a shopping mall for a friend">

You can search floor by floor: check every shop on level 1, then every shop on level 2, and so on. That is **breadth-first**. Or you can follow one corridor to its very end, then come back to the last junction and try the next corridor. That is **depth-first**.

</Analogy>

- <Term def="Breadth-first search: explore a graph level by level using a queue, visiting all nodes 1 edge away, then 2 edges away, and so on.">BFS</Term> keeps the nodes waiting to be visited in a <Term def="A first-in, first-out (FIFO) line: items are added at the back and taken from the front. Python's collections.deque does both in O(1).">queue</Term> (first in, first out). It visits everything 1 edge from the start, then everything 2 edges away, and so on, so the first time it reaches the goal it has used the **fewest edges**: BFS finds shortest paths in graphs where every edge counts the same.
- <Term def="Depth-first search: follow one path as deep as possible, then back up to the most recent choice and try the next option. Uses a stack or recursion.">DFS</Term> keeps them on a <Term def="A last-in, first-out (LIFO) pile: the item added most recently is taken first. A Python list with append() and pop() is a stack.">stack</Term> (last in, first out), or simply uses recursion (the call stack). It follows one route as deep as it can, then backs up to the latest junction. It finds *a* path, often not the shortest.

Both searches look at each node once and each edge once (twice, once from each end, in an undirected graph), so with an adjacency list both take $O(V + E)$ time for $V$ nodes and $E$ edges. (With an adjacency matrix, a $V \times V$ table of yes/no entries, finding one node's neighbours means reading a whole row of $V$ entries, so both become $O(V^2)$.) The essential difference is which end of the frontier you take from: the oldest item (a queue, BFS) or the newest (a stack, DFS). In code there is one more detail: a stack-based DFS must mark a node as visited when it is **popped**, not when it is pushed, so just swapping `popleft()` for `pop()` in `bfs_path` does not give a true DFS. Compare the two functions below: `dfs_path` takes the newest item with `pop()`, skips old copies of places it has already visited, and pushes neighbours in reverse so it explores them in the same order as the picture. Its path has 9 hops where BFS needs only 4: DFS finds *a* path, not the shortest.

<KeyIdea>

BFS and DFS differ in one thing: which end of the frontier the next node comes from. Taking the oldest (a queue) explores level by level and finds the path with the fewest edges; taking the newest (a stack) dives down one route first. With an adjacency list, both take $O(V + E)$ time.

</KeyIdea>

<Mistake title="Forgetting where you have been">

Maps have loops: Home → MRT → Mall → Park → Home is a cycle. Without the `parent` dict (or a `seen` set) that records which places have already been reached, a stack-based DFS walks Home → MRT → Home → MRT … for ever, and a BFS keeps adding copies of the same places to its queue, so it never stops if the goal cannot be reached. In BFS, mark a place as seen when you add it to the queue, so it is queued at most once.

</Mistake>

## Graphs in AI

Graphs are everywhere in AI. (These ideas are taught properly later, starting with [Computational graphs](#/learn/backpropagation/computational-graphs); here just notice the graphs.) When PyTorch, the deep-learning library you will meet later, runs a model it builds a <Term def="A graph whose nodes are operations such as multiply and add, and whose edges show which result feeds into which. Deep-learning libraries build one to compute gradients.">computational graph</Term>: each node is an operation, and each edge says which result feeds into which. Backpropagation walks this graph backwards to get every gradient automatically, which is why this is called automatic differentiation.

Language models also search. **Beam search** builds sentences word by word like a BFS over all possible sentences, but keeps only the $k$ best partial sentences at each level (a top-$k$ selection, as in [Hashing and heaps](#/learn/algorithms-and-complexity/hashing-and-heaps)), because the full tree of sentences grows exponentially. You will meet it properly in [Decoding: greedy, beam search, temperature, top-k and top-p](#/learn/large-language-models/decoding-and-sampling).

For weighted graphs, where edges have different costs (minutes of travel, fares), BFS no longer guarantees the cheapest path; algorithms such as Dijkstra's and A\* extend the same frontier idea with a priority queue (a heap). They are the next step in classical AI search and planning, and worth knowing by name.

</ExamTip>

<Takeaways>

- A graph is a set of nodes joined by edges; in Python, store it as an adjacency list, a dict from each node to the list of its neighbours.
- BFS (queue) explores level by level and finds fewest-edge paths; DFS (stack or recursion) dives deep and backtracks; both are $O(V + E)$.
- Record every node you reach (BFS: when it is queued; stack-based DFS: when it is popped), or the loops in a graph make the search go round in circles.
- When edges have different costs, BFS no longer finds the cheapest path; Dijkstra's algorithm and A\* use a priority queue instead.
- AI is full of graphs: backpropagation walks a computational graph backwards, and beam search is a BFS that keeps only the $k$ best partial sentences at each level.

</Takeaways>
