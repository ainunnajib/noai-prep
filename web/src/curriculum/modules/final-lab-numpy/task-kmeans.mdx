<Analogy title="Bubble tea shops chasing their customers">

Two bubble tea shops open at random spots in a new estate. Every resident walks to the nearer shop. Each shop then moves to the middle of its own customers, and residents choose again. After a few rounds nobody switches and the shops stop moving. The code does exactly that: **assign** every point to its nearest centre, **update** each centre to its customers' mean, **check** whether anything changed. Nobody tells the shops where the groups are: the residents carry no labels, and the groups emerge on their own. That is what makes K-means <Term def="Learning from data that has no labels or answers attached: the algorithm has to find the structure, such as groups, by itself.">unsupervised</Term>.

</Analogy>

## The recipe in the notebook

The notebook gave these steps, and a stub with two functions, `euclidean_distance(a, b)` and `k_means_clustering(points, k, initial_centroids, max_iterations)`:

1. **Initialisation**: use the given `initial_centroids` (no randomness).
2. **Assignment**: for each point, compute its distance to each centroid and assign it to the nearest. *Hint: a helper for the Euclidean distance.*
3. **Update**: move each centroid to the mean of its points. *Hint: decide how to handle empty clusters, e.g. keep the previous centroid.*
4. **Iteration**: repeat 2 and 3 until the centroids no longer change significantly, or `max_iterations` is reached.
5. **Result**: return the list of final centroids, each coordinate rounded to 4 decimal places.

The protected data cell: `points = [(2, 4), (2, 8), (2, 10), (10, 2), (10, 4), (10, 0)]`, `k = 2`, `initial_centroids = [(2, 2), (10, 1)]`, `max_iterations = 10`. Note that the points are Python **tuples**, which cannot be subtracted: `(2, 4) - (2, 2)` is a `TypeError`. Convert them with `np.array` first.

## The distance helper

The <Term def="The straight-line distance between two points: square the difference in each coordinate, add the squares, take the square root.">Euclidean distance</Term> between $a = (a_1, \dots, a_d)$ and $b = (b_1, \dots, b_d)$ is

$$
d(a, b) = \sqrt{\sum_{j=1}^{d} (a_j - b_j)^2}.
$$

Subtract coordinate by coordinate, square each difference, add them up, take the square root: Pythagoras in any number of dimensions $d$. For $(2, 4)$ and $(10, 1)$: $\sqrt{(2-10)^2 + (4-1)^2} = \sqrt{64 + 9} = \sqrt{73} \approx 8.544$. In NumPy, `np.sqrt(np.sum((np.array(a) - np.array(b)) ** 2))`, which works for 2-D, 3-D or any length. Do not hard-code `(a[0] - b[0])` and `(a[1] - b[1])`: hidden tests may use other dimensions.

A few details decide the marks:

- **Return the right type.** A list of tuples of plain floats. Since NumPy 2, `tuple(np.round(c, 4))` prints as `(np.float64(2.0), np.float64(7.3333))`; `round(float(v), 4)` gives `(2.0, 7.3333)`.
- **Round once, at the end.** The official solution rounded the centroids inside the loop and then compared rounded old centroids with unrounded new ones using `==`. That test is never true (7.3333 is not 7.333333…), so its early stop never fired and the loop always ran all 10 iterations. Here that was harmless, but comparing with `np.allclose` and rounding only on return is cleaner.
- **`k` equals `len(initial_centroids)`.** Loop over the given centroids; do not invent new ones.

<Mistake title="Stopping in the wrong place">

`for _ in range(max_iterations)` with a `break` when nothing moves covers both stopping rules. Two slips are common: putting `return` inside the loop (it stops after one iteration), and checking `new_centroids == centroids` on whole arrays in an `if` (NumPy raises "the truth value of an array with more than one element is ambiguous"; use `np.all(...)` or `np.allclose(...)`).

## The vectorised version

The double loop (every point, every centroid) can be replaced by one array operation using <Term def="NumPy's rule for combining arrays of different shapes: dimensions of size 1 are stretched to match the other array.">broadcasting</Term>. With the points `P` of shape `(n, d)` and the centroids `C` of shape `(k, d)`:

- `P[:, None, :]` has shape `(n, 1, d)` and `C[None, :, :]` has shape `(1, k, d)`. Subtracting them stretches both to `(n, k, d)`: every point minus every centroid.
- Squaring, summing over the last axis (`axis=2`) and taking the square root gives the distance matrix `D` of shape `(n, k)`.
- `D.argmin(axis=1)` gives, for each row (each point), the column (centroid) with the smallest distance.
- `P[labels == i]` is a <Term def="Indexing an array with an array of True/False values keeps only the rows where the value is True.">boolean mask</Term>: the rows of cluster $i$. Its `.mean(axis=0)` is the new centroid.

## Convergence and empty clusters

K-means always stops in the end: each assignment and each update can only lower (or keep) the total squared distance from points to their centroids, and there are finitely many ways to split the points. The code needs a rule to notice it has stopped:

- **No change**: the new centroids equal the old ones (exactly, or within a tiny tolerance with `np.allclose`). This is what "no longer change significantly" means.
- **A tolerance**: stop when every centroid moves less than some small number. Too large, and you stop before the clusters are right.
- **`max_iterations`**: a safety net, in case it takes longer.

An **empty cluster** happens when no point is nearest to some centroid. Its mean is a division by zero: NumPy returns `nan` with a "Mean of empty slice" warning, and the `nan` then spreads. The task suggested keeping the previous centroid; re-starting it at a random data point is another common fix. When the starting centroids are chosen randomly, fix a <Term def="A number that sets a random number generator's starting state, so the same 'random' choices happen every run.">seed</Term> (for example `np.random.seed(0)`) so your results can be reproduced.

<Mistake title="The mean of nothing">

`points[labels == i].mean(axis=0)` on an empty selection returns `array([nan, nan])`, not an error, so the bug can stay hidden. Every distance to a `nan` centroid is `nan`, and `np.argmin` treats `nan` as the smallest value, so points start joining the broken cluster. Always guard the update with `if len(members) > 0` (or `np.any(labels == i)`).

</Mistake>
