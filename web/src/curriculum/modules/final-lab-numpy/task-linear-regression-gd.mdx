# DO NOT MAKE CHANGES TO THIS CELL
X = np.array([[2, 2], [2, 4], [2, 6]])
y = np.array([2, 4, 6])
alpha = 0.01
iterations = 1000

def linear_regression_gradient_descent(X: np.ndarray, y: np.ndarray,
                                       alpha: float, iterations: int) -> np.ndarray:
    m, n = X.shape
    theta = np.zeros(n)                   # start at zeros
    for _ in range(iterations):
        errors = X @ theta - y            # h(x) - y for every example, shape (m,)
        gradient = X.T @ errors / m       # one value per theta_j, shape (n,)
        theta = theta - alpha * gradient  # update every theta_j together
    return np.round(theta, 4)             # round once, at the end

print(repr(linear_regression_gradient_descent(X=X, y=y, alpha=alpha, iterations=iterations)))

## What the task gives you

The notebook gives the data in a protected cell, an empty function, and the update rule:

$$
\theta_j := \theta_j - \alpha\,\frac{1}{m}\sum_{i=1}^{m}\left(h_\theta(x^{(i)}) - y^{(i)}\right)x_j^{(i)}
$$

That lesson read the rule symbol by symbol. The recap, in three lines:

- $\theta_j$ is the coefficient for column $j$ of `X` and $m$ is the number of rows; the fraction is the **average of (error × the input in column $j$)**, the slope of the cost $J(\theta) = \frac{1}{2m}\sum_i \left(h_\theta(x^{(i)}) - y^{(i)}\right)^2$, which is 9.33 at $\theta = 0$. Here $i$ counts rows, not iterations, whatever the notebook's wording says.
- $\alpha$ (alpha) is the learning rate, the $\eta$ of earlier lessons; the 2025 notebook calls it alpha, so keep that name in your code.
- The first column of `X` holds 2s, so it already does the intercept's job (the intercept is $2\theta_0$): add no column of your own, and update every $\theta_j$ together from the same old $\theta$.

The data cell holds `X = [[2, 2], [2, 4], [2, 6]]`, `y = [2, 4, 6]`, `alpha = 0.01` and `iterations = 1000`. Three things are *not* said, and you should decide them before typing:

| Not stated | What to do, and why |
|---|---|
| where θ starts | **zeros**, `np.zeros(n)`: the textbook default, and the one the official answer assumes |
| one example per step, or all of them | **all of them**, <Term def="Gradient descent that uses every training example to compute each update. Stochastic gradient descent uses one example per update.">batch gradient descent</Term>: the formula sums over all $m$ examples before each update |
| when to round | **once**, on the returned value: rounding inside the loop changes the answer |

## Three vectorised lines

The sum over $i$, done for every $j$ at once, is one matrix product. Stack the errors into a vector $\mathbf{e}$ of length $m$. Row $j$ of $X^\top$ ("X transpose", `X.T`: rows and columns swapped) holds column $j$ of `X`, so row $j$ of $X^\top\mathbf{e}$ is exactly $\sum_i e_i\,x_j^{(i)}$. The whole update becomes

$$
\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} - \alpha\,\frac{1}{m}\,X^\top\left(X\boldsymbol{\theta} - \mathbf{y}\right).
$$

Writing whole-array operations like this instead of loops over $i$ and $j$ is called <Term def="Using one NumPy operation on whole arrays instead of a Python loop over their elements. NumPy runs the loop in fast compiled code.">vectorisation</Term>. Step through it on the exam data:

<KeyIdea>

Predictions `X @ theta`, errors minus `y`, gradient `X.T @ errors / m`, update `theta - alpha * gradient`. Three lines in a loop (four if you give the predictions their own name), all coefficients updated together, round at the end.

</KeyIdea>

```python
def linear_regression_gradient_descent(X, y, alpha, iterations):
    m, n = X.shape
    theta = [0.0] * n
    for _ in range(iterations):
        h = [sum(theta[j] * X[i][j] for j in range(n)) for i in range(m)]  # predictions
        grad = [sum((h[i] - y[i]) * X[i][j] for i in range(m)) / m          # the task's sum
                for j in range(n)]
        theta = [theta[j] - alpha * grad[j] for j in range(n)]              # all together
    return np.round(np.array(theta), 4)
```

Both return `array([0.003 , 0.9987])`. Notice that the loop version builds the whole `grad` list from the old `theta` before replacing it: that is what "update all $\theta_j$ together" means in code.

<GDRegressionRunner />

Why is the answer after 1000 steps not exactly (0, 1)? The cost surface is a long, narrow valley: steep across, almost flat along. The first few steps race down the steep sides, then θ crawls along the flat floor, and 1000 steps of size 0.01 are not quite enough to finish the crawl. Raising α speeds the crawl, but past about 0.09 the steps across the steep sides overshoot further each time and the run blows up.

## The mistakes that cost marks

Every one of these produces an answer that looks reasonable at a glance. The trick is to know what each one looks like in the output:

<MistakeToggles />

<Mistake title="If your output looks like this, check this">

- **Last digit off** (0.0027, 0.9988): you updated θ₀ before computing θ₁'s gradient. Compute the whole gradient first.
- **Exactly (0, 1)**: you used the sum instead of the mean (no `/ m`), or a factor of 2: you walked faster than the task's rule.
- **A table instead of two numbers**, or a "broadcast" error: mixed shapes, predictions of shape `(m, 1)` against `y` of shape `(m,)`. Keep everything 1-D.
- **Nothing printed**: no `return`. **Three numbers**: an extra bias column. **Eight decimals**: no rounding. **Off in the 2nd or 3rd decimal** (0.012, 0.9946): rounding inside the loop.

</Mistake>

<ExamTip>

- 15 marks is about 20 minutes. Read the shapes, write the three lines, then **check one iteration by hand** before running the full call: (0.08, 0.1867) takes a minute to compute and catches most bugs.
- Use exactly the task's α, iteration count, $\frac{1}{m}$ and starting point: the expected answer is the value after exactly those 1000 steps, not the true minimum.
- In the Prelim, the same algorithm appears as one-step arithmetic ("θ after one update is…") and as definitions: batch gradient descent uses all examples per update; the learning rate sets the step size.

</ExamTip>

<Takeaways>

- The task's $\frac{1}{m}\sum_i (h_\theta(x^{(i)}) - y^{(i)})x_j^{(i)}$ for every $j$ is `X.T @ (X @ theta - y) / m`.
- Start θ at zeros, update every coefficient together from the same old θ, and round once with `np.round(theta, 4)` on the returned value.
- The constant column holds 2s, so the intercept is $2\theta_0$; do not add your own column of 1s.
- Check without an answer key: one step by hand gives (0.08, 0.1867), the cost falls every iteration, and more iterations approach the least-squares answer (0, 1).
- Each classic mistake has a fingerprint: last digit off (sequential update), exactly (0, 1) (sum not mean), a 2 × 3 table (shapes), nothing (no return), three numbers (extra column).

</Takeaways>
