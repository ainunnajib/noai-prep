## Part 1: four one-line building blocks (8 marks)

The model starts from one constant guess and improves it step by step. A <Term def="A number that measures how wrong a prediction is. Training tries to make the average loss small.">loss</Term> $L(y, \hat y)$ measures how wrong a prediction $\hat y$ is for a true value $y$. The task gives two:

$$
\begin{aligned}
L_2(y, \hat y) &= \tfrac12 (y - \hat y)^2 \\
L_1(y, \hat y) &= \lvert y - \hat y \rvert
\end{aligned}
$$

Averaged over all the samples, the L1 loss is the <Term def="Mean absolute error: the average size of the misses, ignoring their sign.">MAE</Term> and the L2 loss is half the <Term def="Mean squared error: the average of the squared misses. Big misses count much more than small ones.">MSE</Term>, the scores the notebook's test cells print.

The <Term def="Minus the derivative of the loss with respect to the prediction. It says which way, and how strongly, to move the prediction to make the loss smaller.">negative gradient</Term> $-\frac{\partial L}{\partial \hat y}$ says which way to nudge the prediction to make the loss smaller, and how hard.

- **L2.** By the chain rule, $\frac{\partial}{\partial \hat y}\tfrac12(y - \hat y)^2 = (y - \hat y) \times (-1)$. So the negative gradient is $y - \hat y$, the plain <Term def="Truth minus prediction, y − ŷ: how far, and in which direction, the prediction missed.">residual</Term>. A far-away point pulls hard.
- **L1.** The slope of $\lvert y - \hat y \rvert$ is $-1$ when the prediction is too small and $+1$ when it is too big. So the negative gradient is $\operatorname{sign}(y - \hat y)$: $+1$, $-1$, or $0$ when $y = \hat y$. At that one point the slope is undefined, and the notebook allows any value in $[-1, 1]$ (a <Term def="A stand-in for the derivative at a corner where the true derivative does not exist. For |x| at 0, any value between −1 and 1 is allowed.">sub-gradient</Term>). `np.sign` gives 0. Every point pulls with the same strength, however far away it is.

Before any tree, the model needs one constant for every sample, $F_0$. The best constant is the one where all the pulls cancel. Try it:

<KeyIdea>

The best constant for L2 is the **mean** (the residuals add up to 0 there). The best constant for L1 is the **median** (as many $+1$ pulls as $-1$ pulls). That is why Q1.3 returns the median and Q1.4 the mean.

</KeyIdea>

## Part 2: the class and the fit loop (12 marks)

Here is the whole algorithm. Each line is one of the TODOs.

$$
\begin{aligned}
F_0 &= \text{mean (L2) or median (L1) of } y \\
r_i &= -\frac{\partial L(y_i, \hat y)}{\partial \hat y}\Big|_{\hat y = F_{m-1}(x_i)} \\
h_m &= \text{a small tree fitted to } (x_i, r_i) \\
F_m(x) &= F_{m-1}(x) + \eta \, h_m(x)
\end{aligned}
$$

- $F_m(x)$ is the model's prediction after $m$ trees, and `current_pred` holds $F_m$ for every training row.
- $r_i$ is the negative gradient from Part 1 for sample $i$, measured at the current prediction. These are the tree's targets, called `residuals` in the code even when they are signs (L1).
- $h_m$ is tree number $m$, a `DecisionTreeRegressor` with at most `max_depth` levels, fitted only on this round's subsample of rows. Each leaf predicts the average target of its rows.
- $\eta$ (eta) is the <Term def="The fraction of each tree's prediction that is added to the model, usually 0.01 to 0.3. Smaller steps need more trees but usually generalise better.">learning rate</Term>: only a fraction of each tree's answer is added.

After $M$ trees, the prediction for a new $x$ is

$$
F_M(x) = F_0 + \eta \sum_{m=1}^{M} h_m(x),
$$

which is exactly what `predict` computes.

<KeyIdea>

The class just organises one loop. fit: start at $F_0$; repeat (a) compute the negative gradient, (b) pick rows, (c) fit a tree to it, (d) add $\eta \times$ tree to **every** row, (e) store the tree. predict: start at $F_0$ and add $\eta \times$ each stored tree.

</KeyIdea>

<Note title="Why the L1 model scores so badly (it is not a bug)">

The notebook's test cell prints a test MSE of about **15,986** for `criterion="l1"` and **1,268** for `"l2"`. If your L1 test MSE is about 16,000, only a little below the 17,110 baseline of predicting the mean, your code is probably correct. Each L1 tree is fitted to signs, values between $-1$ and $+1$, so one round moves a prediction by at most $\eta \times 1 = 0.1$. A hundred rounds move it at most 10 units, but the targets spread over hundreds of units (standard deviation 132.5). Real L1 boosting libraries fix this with a "line search": they replace each leaf's value by the median raw residual in that leaf. With that change the test MSE drops below 1,800. The exam did not ask for it: in the exam's algorithm, switching to L1 changes only the targets, `sign(y - F)`, which is why the Final's MCQ above has the answer "Line A only". The leaf-median line search is an optional improvement, not a required change.

</Note>

## Part 3: early stopping (5 bonus marks)

More trees keep lowering the **training** error, but after a while the model starts to memorise noise. That is <Term def="When a model fits the training data so closely, noise included, that it does worse on new data.">overfitting</Term>. The cure is to watch a <Term def="Data held back from training and used only to check the model while you make choices, such as when to stop.">validation set</Term> after every tree and stop when it stops improving.

<Analogy title="Seasoning soup">

You add salt one pinch at a time and taste after each pinch. You remember the best taste so far. If a few pinches in a row have not made it better, you stop, and you throw away the over-salted spoonfuls added after the best moment. The pinches are trees, the tasting is the validation loss, and "a few in a row" is the patience.

</Analogy>

`GBREarlyStop.fit(X_train, y_train, X_val, y_val, patience=10, min_delta=1e-4)` keeps three trackers. The scaffold gives them, and you update them in the loop:

- `best_val_loss`: the lowest validation loss so far (starts at infinity);
- `best_n_estimators`: **how many trees** had been added when that best happened;
- `patience_counter`: how many trees in a row have **not** improved on the best by more than `min_delta`.

<EarlyStopRunner />

<Mistake title="Early-stopping slips">

- `best_n_estimators = m` instead of `m + 1`. After the first tree, `m` is 0 but one tree exists, so you would keep one tree too few.
- Never updating `best_n_estimators`. The given trim `self.trees[:0]` then keeps **no** trees. The visible check only asks for fewer than 500 trees, so it still passes while the model predicts $F_0$ for everyone.
- Updating `F_val` with a different tree, or forgetting it, so the validation loss never changes.
- `>` versus `>=`. The code comment says "exceeds" (`>`), but the text and the official solution stop when the counter **reaches** the patience (`>=`). With patience 1 on the notebook's data (and scikit-learn 1.9), `>=` stops after 125 trees and keeps 124; `>` runs on to tree 249 and keeps 247. Other scikit-learn versions stop elsewhere, because they break ties between equally good splits differently. Use `>=`.
- Changing the defaults. `criterion` defaults to `'l2'` in `GradientBoostingRegressor` but to `"l1"` in `GBREarlyStop`. Leave both as given; the test cell passes `criterion="l2"` explicitly.

</Mistake>

<Takeaways>

- Negative gradients: L2 gives the residual `y - y_pred`; L1 gives `np.sign(y - y_pred)`. Initial prediction: mean for L2, median for L1, returned as one `np.float64`.
- fit: start every row at $F_0$, then repeat (a) negative gradient, (b) subsample, (c) fit a tree, (d) `current_pred += learning_rate * tree.predict(X)` for **all** rows, (e) store the tree.
- predict: $F_0 + \eta \sum_m h_m(x)$. Q1.5's slot is `predict`, not `__init__`, and forgetting `learning_rate` there ruins the model.
- Early stopping updates the validation predictions with the same tree, records the best loss and `best_n_estimators = m + 1`, stops after `patience` non-improving trees (`>=`), and keeps only the best trees.
- A bad L1 score is expected: sign targets move predictions at most $\eta$ per tree.

</Takeaways>
