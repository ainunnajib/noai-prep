Nobody trains BERT from scratch for a school project: it took a large lab days of computing. Instead, you download it: the **Hugging Face Hub** hosts millions of pretrained models, and the `transformers` library loads any of them in one line. This lesson goes from a one-line pipeline to the parts inside it, then to fine-tuning, including the label value $-100$ that NOAI Final questions love.

## Pipelines: one line from text to answer

<Analogy title="A drinks vending machine">

You press one button and a cup of teh tarik comes out. Inside there is a cup dispenser, a mixer and a pump, each doing one job in order. A Hugging Face **pipeline** is the button: it hides a tokeniser, a model and a post-processing step.

</Analogy>

A model on the Hub is named `owner/model-name`, for example `distilbert/distilbert-base-uncased-finetuned-sst-2-english`: a small BERT (DistilBERT) fine-tuned on SST-2, a dataset of film-review sentences labelled positive or negative. The first time you use a name, `transformers` downloads the model's weights, its <Term def="A small file (config.json) that records a model's architecture: number of layers, hidden size, vocabulary size, label names and so on. Hugging Face reads it to build the right model class.">config</Term> and its tokeniser files, and caches them on disk.

```python
from transformers import pipeline

clf = pipeline("sentiment-analysis",
               model="distilbert/distilbert-base-uncased-finetuned-sst-2-english")
results = clf(["The chicken rice here is amazing!",
               "The queue was long and the food was cold."])
for r in results:
    print(r)
```

```text
{'label': 'POSITIVE', 'score': 0.9998237490653992}
{'label': 'NEGATIVE', 'score': 0.9996987581253052}
```

The pipeline returns one dictionary per text: the predicted label and the model's probability for it.

Other task names work the same way: `"ner"` (tag people, places and organisations), `"fill-mask"` (BERT's fill-in-the-blank game), `"text-generation"` (GPT-style), `"zero-shot-classification"`, `"automatic-speech-recognition"` (for example with Whisper) and `"image-classification"`. Version 4 of `transformers` also has `"summarization"`, `"translation"` and `"question-answering"` pipelines, but current version 5 releases have dropped all three, so for those you call the model directly (the figure's "summary" task shows how). It is good practice to always pass `model=` explicitly, so you know exactly which model you are running.

## The three stages by hand

**Stage 1: the tokeniser.** `AutoTokenizer.from_pretrained(name)` loads the tokeniser that matches the model (Hugging Face spells it *tokenizer* in its code). Calling it on text returns a dictionary of tensors:

- `input_ids`: the token ids, shape $(B, T)$ for $B$ texts of $T$ tokens, including the special tokens such as `[CLS]` (101) and `[SEP]` (102).
- `attention_mask`: 1 for a real token, 0 for padding, same shape. The model uses it to stop attention from looking at padding, as in the [padding mask](#/learn/attention-and-transformers/scaled-dot-product-attention).
- for BERT, also `token_type_ids`: 0 for the first sentence and 1 for the second, when you feed two sentences as a pair.

A batch must be a rectangle to become a tensor, so the tokeniser can **pad** short texts and **truncate** long ones:

<TokenizerBatch />

**Stage 2: the model.** `AutoModelForSequenceClassification.from_pretrained(name)` reads the config, builds the right architecture with a classification head, and loads the weights. Its output has `.logits` of shape $(B, \text{num\_labels})$.

**Stage 3: post-processing.** Softmax turns logits into probabilities, `argmax` picks the class, and `model.config.id2label` turns the class number into a name.

```python
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

name = "distilbert/distilbert-base-uncased-finetuned-sst-2-english"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForSequenceClassification.from_pretrained(name)
model.eval()

texts = ["The chicken rice here is amazing!",
         "The queue was long and the food was cold."]
enc = tok(texts, padding=True, return_tensors="pt")      # stage 1
print(enc["input_ids"].shape)
print(enc["attention_mask"])

with torch.no_grad():                                      # stage 2
    logits = model(**enc).logits
print(logits)

probs = logits.softmax(dim=-1)                             # stage 3
for p in probs:
    k = p.argmax().item()
    print(model.config.id2label[k], round(p[k].item(), 4))
```

The `Auto` classes pick the architecture from the config. The part after `AutoModelFor` says which **head** sits on top, and therefore what shape the logits have ($V$ is the vocabulary size):

- `AutoModel`: no head. It returns the hidden states, shape $(B, T, d)$, for example to use as embeddings.
- `AutoModelForSequenceClassification`: one label per text, from `[CLS]`. Logits $(B, \text{num\_labels})$. Models: BERT, DistilBERT, RoBERTa.
- `AutoModelForTokenClassification`: one label per token. Logits $(B, T, \text{num\_labels})$. Models: BERT-style NER models.
- `AutoModelForMaskedLM`: a word for every position (fill-mask). Logits $(B, T, V)$. Models: BERT.
- `AutoModelForCausalLM`: the next token. Logits $(B, T, V)$. Models: GPT-2, Llama, Qwen.
- `AutoModelForSeq2SeqLM`: an encoder-decoder, used with `.generate()`. Logits $(B, T_\text{out}, V)$. Models: T5, BART, MarianMT.

<Reveal label="Going further: summarising with T5 in code">

For an encoder-decoder such as T5, `model.generate(**enc)` runs the [decoding loop](#/learn/pretrained-models-text-speech/encoder-decoder-models) for you, and `tok.decode(ids, skip_special_tokens=True)` turns the output ids back into text. This is how you summarise in any version of `transformers`:

```python
import textwrap
from transformers import AutoTokenizer, AutoModelForSeq2SeqLM

tok = AutoTokenizer.from_pretrained("google-t5/t5-small")
model = AutoModelForSeq2SeqLM.from_pretrained("google-t5/t5-small")
text = ("Singapore's public libraries will open longer hours from next month, "
        "the National Library Board said on Monday. Twelve libraries will stay "
        "open until 11pm on weekdays, two hours later than now, after surveys "
        "showed that many students and working adults wanted quiet places to "
        "study in the evenings. The board will also add more study seats and "
        "power points at its busiest branches, including those in Jurong, "
        "Tampines and Woodlands.")
enc = tok("summarize: " + text, return_tensors="pt")      # task prefix
out = model.generate(**enc, max_new_tokens=40)
summary = tok.decode(out[0], skip_special_tokens=True)
print(textwrap.fill(summary, width=60))                   # wrap long lines
```

<Mistake title="Mixing tokenisers and models">

Always load the tokeniser and the model from the **same** name. ## Fine-tuning with your own labels

The SST-2 model above only knows "positive" and "negative" film reviews. To build your own classifier, say for hawker-centre reviews, start from a pretrained model **without** a task head and let `transformers` add a fresh one:

<Steps title="Fine-tuning a sequence classifier">
  <Step title="Load the body, add a new head">
    `AutoModelForSequenceClassification.from_pretrained(name, num_labels=2)` loads the pretrained encoder and adds a **randomly initialised** classification head. Hugging Face warns that weights such as `classifier.weight` and `classifier.bias` are newly initialised: that is expected, because training them is the whole point.
  </Step>
  <Step title="Tokenise the data">
    Run the tokeniser on your texts with `padding=True, truncation=True`, and keep the labels as a tensor of class numbers.
  </Step>
  <Step title="Train gently">
    Use AdamW with a **small** learning rate, typically $2 \times 10^{-5}$ to $5 \times 10^{-5}$, for 2 to 4 epochs on real data. Passing `labels=` to the model makes it compute the cross-entropy loss for you, in `outputs.loss`.
  </Step>
  <Step title="Evaluate">
    Check accuracy or F1 on a validation set the model never trained on, and stop when the validation loss stops improving.
  </Step>
</Steps>

Here is the whole loop on 8 example sentences (far too few for real use, but enough to watch the loss fall). It uses DistilBERT, a 6-layer, 66-million-parameter version of BERT:

```python
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

torch.manual_seed(0)
name = "distilbert/distilbert-base-uncased"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForSequenceClassification.from_pretrained(name, num_labels=2)

texts = ["the laksa was shiok", "worst kopi ever", "service was fast and friendly",
         "the food was cold and bland", "love this hawker stall", "the queue was terrible",
         "great value for money", "never coming back again"]
labels = torch.tensor([1, 0, 1, 0, 1, 0, 1, 0])         # 1 = positive, 0 = negative

batch = tok(texts, padding=True, truncation=True, max_length=32, return_tensors="pt")
optimiser = torch.optim.AdamW(model.parameters(), lr=5e-5)

model.train()
for epoch in range(1, 31):
    out = model(**batch, labels=labels)    # with labels, the model also returns the loss
    out.loss.backward()
    optimiser.step()
    optimiser.zero_grad()
    if epoch % 10 == 0:
        print(f"epoch {epoch}: loss {out.loss.item():.4f}")

model.eval()
with torch.no_grad():
    test = tok(["the chicken rice was shiok", "cold and bland"],
               padding=True, return_tensors="pt")
    probs = model(**test).logits.softmax(dim=-1)
print(probs.round(decimals=3))
```

```text
epoch 10: loss 0.1713
epoch 20: loss 0.0242
epoch 30: loss 0.0071
tensor([[0.0100, 0.9900],
        [0.9940, 0.0060]])
```

Column 1 is "positive", so the model now calls "the chicken rice was shiok" positive (0.99) and "cold and bland" negative. This is the same [training loop](#/learn/pytorch/training-loop) as always: forward, loss, `backward`, `step`, `zero_grad`.

<Reveal label="Going further: the Trainer runs the loop for you">

The library also has a `Trainer` that runs this loop for you, with batching, padding, a learning-rate schedule and logging built in. Continuing with the same `name`, `tok`, `texts` and `labels`, and a fresh copy of the model:

```python
from transformers import Trainer, TrainingArguments

model = AutoModelForSequenceClassification.from_pretrained(name, num_labels=2)
enc = tok(texts, truncation=True, max_length=32)    # Trainer pads each batch
train_ds = [{"input_ids": enc["input_ids"][i],
             "attention_mask": enc["attention_mask"][i],
             "labels": int(labels[i])} for i in range(len(texts))]

args = TrainingArguments(output_dir="out", learning_rate=5e-5,
                         num_train_epochs=10, per_device_train_batch_size=4,
                         logging_steps=5, report_to="none")
trainer = Trainer(model=model, args=args, train_dataset=train_ds,
                  processing_class=tok)
trainer.train()
```

## Labels of −100: "do not mark this one"

<Analogy title="Marking only what was attempted">

A teacher marking a worksheet skips the blank answer spaces at the end of the page: they were never questions. The label value $-100$ is that instruction for the loss: **skip this position**.

</Analogy>

You met $-100$ in [Tokenisation](#/learn/text-as-data/tokenisation): it marks a label that the loss must skip. PyTorch's `nn.CrossEntropyLoss` and `F.cross_entropy` have an argument `ignore_index`, and its default value is $-100$. Any position whose label is $-100$ adds nothing to the loss and is **not counted** in the average:

$$
\mathcal{L} = \frac{1}{|S|} \sum_{i \in S} -\ln p_i(y_i)
$$

$$
S = \{\, i : y_i \neq -100 \,\}
$$

- $y_i$ is the label at position $i$, and $p_i(y_i)$ is the probability the model gives that label.
- $S$ is the set of positions that are scored, and $|S|$ is how many there are. The average divides by $|S|$, not by the total length.

You meet $-100$ wherever a sequence has positions that should not be graded:

- **Token classification** (such as NER): special tokens, padding, and often the later pieces of a split word.
- **Language modelling**: padding, and when fine-tuning a chatbot, the prompt tokens, so the model is only graded on the answer.
- **BERT's masked language modelling**: every position not chosen by the 15% rule, as you saw in [the BERT lesson](#/learn/pretrained-models-text-speech/bert-and-gpt).

<IgnoreIndexMask />

Here is cross-entropy with `ignore_index` written from scratch in NumPy, on 5 positions and 3 classes where the last 2 positions are padding. Run it, then set the first label to $-100$ as well and predict the change before you run it again.

<PyRunner packages={['numpy']} rows={20} code={ceCode} />

You should see `0.2933`, the average over the 3 real positions only, which is exactly what PyTorch's `F.cross_entropy(logits, labels)` returns, since its `ignore_index` is $-100$ by default. The buggy labels give `0.6154`: each padded row has three equal logits, so it adds a loss of $\ln 3 \approx 1.10$, and the average is now over 5 positions. That is the classic slip of labelling padding with the `[PAD]` id 0: label 0 is a real class (in NER, "O"), so padding gets graded. The pad id belongs in `input_ids`, and $-100$ only in the labels.

<Reveal label="Going further: lining up word labels with tokens for NER">

NER labels follow the **BIO** scheme: `B-PER` marks the first word of a person's name, `I-PER` a later word inside the same name, `B-LOC` the first word of a location, and `O` a word outside any name. The model used below, `dslim/bert-base-NER`, numbers its 9 tags from 0 (`O`), so `B-PER` = 3, `I-PER` = 4 and `B-LOC` = 7.

The labels come per **word** but the model sees **tokens**, so you line them up with the tokeniser's `word_ids()`, which says which word each token came from (`None` for special tokens):

```python
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("dslim/bert-base-NER")
words = ["Joseph", "Schooling", "won", "gold", "in", "Rio"]
word_labels = [3, 4, 0, 0, 0, 7]          # B-PER, I-PER, O, O, O, B-LOC
enc = tok(words, is_split_into_words=True)
print(tok.convert_ids_to_tokens(enc["input_ids"]))
print(enc.word_ids())

labels, prev = [], None
for w in enc.word_ids():
    if w is None:
        labels.append(-100)              # [CLS], [SEP]: not scored
    elif w != prev:
        labels.append(word_labels[w])    # first piece: the word's label
    else:
        labels.append(-100)              # later pieces: not scored
    prev = w
print(labels)
```

```text
['[CLS]', 'Joseph', 'School', '##ing', 'won', 'gold', 'in', 'Rio', '[SEP]']
[None, 0, 1, 1, 2, 3, 4, 5, None]
[-100, 3, 4, -100, 0, 0, 0, 7, -100]
```

When batches are padded later, Hugging Face's `DataCollatorForTokenClassification` fills the labels of padding positions with $-100$ too.

</Reveal>

<ExamTip>

Common NOAI checks: the attention mask is **1 for real tokens, 0 for padding**; padded or special positions in the **labels** are $-100$, the default `ignore_index` of cross-entropy; the loss is averaged over the scored positions only; a freshly added head is **randomly initialised** and must be trained; fine-tuning BERT uses a **small learning rate** ($2 \times 10^{-5}$ to $5 \times 10^{-5}$), and a large one makes validation loss rise as the pretrained knowledge is overwritten.

</ExamTip>

## Open-source models or an API?

There are two ways to use a pretrained language model:

| | Open-weights models (download) | API-based models (call over the internet) |
|---|---|---|
| Examples | BERT, DistilBERT, T5, Whisper, Llama, Qwen, Gemma on the Hugging Face Hub | OpenAI's GPT models, Claude, Gemini |
| Where it runs | your own computer or GPU | the provider's servers |
| Internet needed | only to download once | for every call |
| Fine-tuning | full control: any layer, any method | limited, or not offered |
| Data privacy | your data never leaves your machine | your text is sent to the provider |
| Cost and size | free weights, but you pay in hardware; size limited by your GPU memory | pay per token; can use the very largest models |

An API call is just a web request (HTTP, the way a browser fetches a page) carrying your text and a secret key, and the reply comes back as JSON, text laid out like a Python dictionary.

<Reveal label="Going further: what an API request looks like">

A typical chat-style request looks like this (it needs a provider and a key, so there is no output to show):

```python
import requests

reply = requests.post(
    "https://api.example.com/v1/chat/completions",          # the provider's address
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={"model": "some-model",
          "messages": [{"role": "user", "content": "Classify: 'The laksa was shiok!'"}]},
).json()
print(reply["choices"][0]["message"]["content"])
```

</Reveal>

At IOAI 2026 the contest machines had **no internet** apart from a whitelist of documentation sites, so you could only use models already on the machine, plus an official assistant LLM with a short output limit. That is why the skills in this lesson, loading, running and fine-tuning local models, matter most.

<Takeaways>

- `pipeline("task", model=...)` = **tokeniser → model → post-processing**. You can run each stage yourself with `AutoTokenizer` and an `AutoModelFor...` class from the same model name.
- The tokeniser returns **`input_ids`** (token ids with `[CLS]`/`[SEP]`) and an **`attention_mask`** (1 = real token, 0 = padding); `padding=True` and `truncation=True` make a batch rectangular.
- To fine-tune, load the pretrained body with a new head (`num_labels=...`), pass `labels=` to get `outputs.loss`, and train with AdamW at a small learning rate (about $2 \times 10^{-5}$ to $5 \times 10^{-5}$), in your own loop or with `Trainer`.
- Label **$-100$** = "do not score": cross-entropy's default `ignore_index` skips it and averages over the remaining positions. Use it for padding, special tokens and extra word pieces, never as an input id.
- **Open-weights** models run locally (private, fine-tunable, offline); **API** models run on a provider's servers (largest models, pay per call, needs internet).

</Takeaways>
