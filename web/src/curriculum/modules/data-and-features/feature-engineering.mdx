A model can only learn from the numbers you hand it. **Feature engineering** means building better numbers: new columns, computed from the raw data, that put the pattern in plain sight. With the right feature, even the simplest model can solve a problem that looked impossible.

<Analogy title="Choosing durians at a stall in Geylang">

The uncle says the best durians are dense. Sorting by **weight** alone fails (a heavy durian may just be a big one), and so does sorting by **size**. But divide one by the other, weight per volume, and the good ones jump out. No new data: just the data you had, combined into one number that matters.

</Analogy>

A <Term def="One input column of a dataset, such as a flat's floor area or a reading's timestamp. A model sees each example as a list of feature values.">feature</Term> is one input column of your data, and <Term def="Creating new input columns from existing ones (or from raw data such as text, dates or sensor readings), using knowledge of the problem, so that a model can learn more easily.">feature engineering</Term> creates new ones from old: powers and products, ratios and date parts, and window statistics for sequences.

## A new feature can make a hard problem easy

Here are seven points on a number line. Class A sits in the middle and class B on both sides:

| $x$ | $-3$ | $-2$ | $-1$ | $0$ | $1$ | $2$ | $3$ |
|---|---|---|---|---|---|---|---|
| class | B | B | A | A | A | B | B |

A <Term def="A classifier whose decision boundary is straight: a point, a line or a flat plane. It works out a weighted sum of the features and compares it with a threshold.">linear classifier</Term> on one feature can make only **one cut**: "everything bigger than $t$ is B, everything smaller is A" (or the other way round). Wherever you put the cut, B points sit on both sides of A, so at least two points are wrong. But the classes differ in **distance from 0**, and $x^2$ measures exactly that. Try it below on a bigger version of the same pattern, and then try the two 2-D datasets, where no straight line can separate the classes either.

<FeatureLift />

What happened? We replaced each input $x$ by a longer list of features, written $\phi(x)$ (the Greek letter phi):

$$
\phi(x) = (x,\ x^2)
$$

The classifier is still linear: it computes a weighted sum of its features and compares it with 0,

$$
w_1 x + w_2 x^2 + b > 0 \;\Rightarrow\; \text{class B}
$$

where $w_1$ and $w_2$ are <Term def="Numbers the model learns, one per feature, that say how much each feature counts in the weighted sum.">weights</Term> and $b$ is a constant called the bias. With $w_1 = 0$, $w_2 = 1$ and $b = -2.5$ the rule reads "$x^2 > 2.5$". That is a straight cut in the new feature, but in the original $x$ it is two cuts, at $x = \pm\sqrt{2.5} \approx \pm 1.58$. The same trick with $x_1^2 + x_2^2$ (squared distance from the centre) turns a straight cut into a circle, and $x_1 x_2$ (positive exactly when $x_1$ and $x_2$ have the same sign) solves the quadrants.

<KeyIdea>

A linear model draws straight boundaries, but only in the features you give it. Add the right non-linear feature ($x^2$, $x_1^2 + x_2^2$, $x_1 x_2$) and a straight boundary in the new features becomes a curved one in the old. Good features encode what you know about the problem.

</KeyIdea>

<Steps title="Separate the seven points by hand">
  <Step title="Compute the new feature">
    Square every $x$: $(-3, -2, -1, 0, 1, 2, 3) \to (9, 4, 1, 0, 1, 4, 9)$.
  </Step>
  <Step title="Look at each class">
    Class A (the middle three) has $x^2$ values $1, 0, 1$: never more than 1. Class B has $9, 4, 4, 9$: never less than 4.
  </Step>
  <Step title="Pick a threshold in the gap">
    Any value between 1 and 4 works. Halfway is $2.5$: predict B when $x^2 > 2.5$. All seven points are now correct.
  </Step>
  <Step title="Translate back">
    $x^2 > 2.5$ means $x > 1.58$ or $x < -1.58$: one cut on $x^2$ is two cuts on $x$.
  </Step>
</Steps>

Here is the same experiment with a real model. <Term def="A simple classifier (you will study it in the classification module) that learns weights for a weighted sum of the features and predicts a class from it. Its decision boundary is straight.">Logistic regression</Term> learns a straight boundary, so on $x$ alone it gives up and predicts B for everyone (4 out of 7 right). Add the column $x^2$ and it gets all seven.

<PyRunner packages={['numpy', 'scikit-learn']} code={`import numpy as np
from sklearn.linear_model import LogisticRegression

x = np.array([-3, -2, -1, 0, 1, 2, 3])
# 1 = class B, 0 = class A
y = np.array([1, 1, 0, 0, 0, 1, 1])
print("x squared:", x ** 2)

# one feature: x
X_raw = x.reshape(-1, 1)
# two features: x and x**2
X_new = np.column_stack([x, x ** 2])

m_raw = LogisticRegression().fit(X_raw, y)
m_new = LogisticRegression().fit(X_new, y)
print("x only     :", m_raw.predict(X_raw), "accuracy", round(m_raw.score(X_raw, y), 3))
print("x and x**2 :", m_new.predict(X_new), "accuracy", round(m_new.score(X_new, y), 3))`} />

## Polynomial and interaction features

The features in the visual come from two recipes. A <Term def="A power of one feature, such as x² or x³, or a product of several features, such as x₁x₂ or x₁²x₂. Adding them lets a linear model fit curves.">polynomial feature</Term> is a power of a feature, such as $x_1^2$. An <Term def="The product of two (or more) different features, such as x₁ × x₂. It lets the effect of one feature depend on the value of another.">interaction feature</Term> is a product of different features, such as $x_1 x_2$: it lets the effect of one feature depend on another. Ice-cream sales may rise with temperature much more on weekends than on weekdays, and a column `temperature × is_weekend` captures exactly that.

scikit-learn's `PolynomialFeatures(degree=d)` builds every power and product up to total degree $d$, plus a column of 1s (the "bias"). Build some and watch the count:

<PolynomialExpander />

How many columns does degree 2 give with $p$ input features? (We write $p$ here because $n$ usually counts examples and $d$ is already the degree.) Count them: the bias $1$, the $p$ originals, the $p$ squares, and one product for every pair of different features, $\frac{p(p-1)}{2}$ of them:

$$
1 + p + p + \frac{p(p-1)}{2} = \frac{(p+1)(p+2)}{2}
$$

For $p = 2$ that is $\frac{3 \times 4}{2} = 6$ columns, namely $1, x_1, x_2, x_1^2, x_1x_2, x_2^2$; for $p = 3$ it is $\frac{4 \times 5}{2} = 10$. Set `include_bias=False` and there is one fewer. For any degree $d$ the count is $\binom{p+d}{d} = \frac{(p+d)!}{p!\, d!}$, read "$p + d$ <Term def="The number of ways to pick k items from n, written C(n, k) or with n above k in brackets. For example, there are 6 ways to pick 2 of 4 items.">choose</Term> $d$", where the factorial $4! = 4 \times 3 \times 2 \times 1$; for $d = 2$ it gives the same answers.

```python
import numpy as np
from sklearn.preprocessing import PolynomialFeatures

X = np.array([[2, 3]])                 # one row: x1 = 2, x2 = 3
poly = PolynomialFeatures(degree=2)
print(poly.fit_transform(X))
print(poly.get_feature_names_out())
```

```text
[[1. 2. 3. 4. 6. 9.]]
['1' 'x0' 'x1' 'x0^2' 'x0 x1' 'x1^2']
```

(scikit-learn counts features from 0, so its `x0` is our $x_1$.) Check the row: $1,\ 2,\ 3,\ 2^2 = 4,\ 2 \times 3 = 6,\ 3^2 = 9$.

<Mistake title="“More features can only help”">

Every extra column gives the model another way to fit noise in the training data, which is **overfitting**. Polynomial features also grow quickly: degree 2 on 100 features already gives 5,151 columns. And powers stretch scales: if income is about 5,000, then income² is about 25,000,000, so standardise the new columns before using a model that cares about scale (see [Scaling, normalisation and standardisation](#/learn/data-and-features/scaling-and-normalisation)). Add features that you have a reason to expect will help, then check on validation data.

</Mistake>

## Features from what you know: ratios, dates and bins

The most valuable features usually come from knowing the problem, not from a formula.

- **Ratios and differences.** A 90 m² flat sold for 540,000 dollars costs 540,000 ÷ 90 = 6,000 dollars per m², a number that compares flats of different sizes fairly. "Remaining lease = 99 − (sale year − lease start year)" often predicts HDB resale prices better than either year alone.
- **Date and time parts.** A raw timestamp is one ever-growing number, but taxi demand repeats every day and every week. Extract `hour`, `day_of_week`, `month` and flags such as `is_weekend` or `is_public_holiday`.
- **Bins.** <Term def="Turning a number into a small number of ranges (categories), for example age into child, teen, adult and senior. Also called discretisation.">Binning</Term> turns a number into ranges, such as age into child / teen / adult / senior. It helps when the effect jumps at known boundaries (concession fares), at the cost of throwing away detail inside each bin.

Clock time has a twist: it wraps around. As numbers, 23:00 and 01:00 are 22 apart, yet they are only two hours apart in real life. The fix is to put the hour on a circle with two features, $\left(\sin \tfrac{2\pi h}{24},\ \cos \tfrac{2\pi h}{24}\right)$, where $h$ is the hour. Picture a clock hand of length 1 that starts pointing straight up and turns clockwise: <Term def="Turn a hand of length 1 clockwise by an angle θ from straight up. Then sin θ is how far its tip is to the right of the centre and cos θ how far it is above the centre (negative means left or below). So sin 0° = 0 and cos 0° = 1, sin 90° = 1 and cos 90° = 0. This cos is the cosine you met with the dot product.">sin and cos</Term> of the angle it has turned give the x and y positions of its tip. The angles here are in <Term def="A unit for angles in which a full turn is 2π (about 6.28) instead of 360°. NumPy's sin and cos expect radians.">radians</Term>, where a full turn is $2\pi$ instead of 360°, so $\tfrac{2\pi h}{24}$ is simply $\tfrac{h}{24}$ of a full turn: 15° for every hour (6:00 is 90°, 12:00 is 180°). In degrees the features are $(\sin 15h^\circ,\ \cos 15h^\circ)$: the position of the hour hand on a 24-hour clock.

<CyclicHour />

All of these take one line each in pandas. Run it and check the `fare_per_km` and `is_weekend` columns (19 February 2027 is a Friday, so `day_of_week` is 4):

<PyRunner packages={['numpy', 'pandas']} code={`import numpy as np

rides = pd.DataFrame({

## Sliding windows: features from sequences

Sensor readings, heartbeats, stock prices and audio are long sequences, and they rarely have the same length. Most models want a fixed-size list of numbers per example. The standard fix is a <Term def="A block of the k most recent readings that moves along a sequence one step at a time. Statistics computed inside it are called rolling (or moving) statistics.">sliding window</Term>: take the last $k$ readings, summarise them with a few <Term def="Numbers that describe a group of values, such as the mean, standard deviation, minimum and maximum.">summary statistics</Term>, then slide one step and repeat.

<Analogy title="The doctor's summary">

A smartwatch records your heart rate every second, but your doctor does not read 600,000 numbers. She says "average 72, very steady this week". That is two features, a mean and a measure of spread, computed over a window.

</Analogy>

For a window of size $k$ ending at time $t$, the two most common window features are

$$
m_t = \frac{1}{k}\sum_{i=t-k+1}^{t} x_i
$$

$$
s_t = \sqrt{\frac{1}{k}\sum_{i=t-k+1}^{t} \left(x_i - m_t\right)^2}
$$

- $x_i$ is the reading at time $i$, and the sums run over the $k$ readings from $t-k+1$ up to $t$.
- $m_t$ is the **rolling mean**: the typical level inside the window.
- $s_t$ is the **rolling standard deviation**: the typical distance of a reading from that level, i.e. how much the signal shakes.

The mean and the variance ($s_t^2$) are the first two <Term def="Standard summary numbers of a distribution: the mean (1st moment), the variance (2nd), skewness (3rd) and kurtosis (4th). The IOAI syllabus calls window features built from them 'statistical moment-based features'.">statistical moments</Term>, which is why the IOAI syllabus calls these "moment-based features". The next two describe shape, using each reading's z-score $z_i = (x_i - m_t)/s_t$ inside the window. **Skewness**, the mean of $z_i^3$, measures lopsidedness (positive for a long tail to the right), and **kurtosis**, the mean of $z_i^4$, measures how heavy the tails are (how often extreme readings appear). Minimum, maximum and slope are also popular.

<SlidingWindowFeatures />

<Steps title="Rolling mean and standard deviation by hand, with k = 4">
  <Step title="The data">
    Heart rate readings: $70, 72, 70, 72, 90, 110, 90, 110$. The first full window ends at the 4th reading, so readings 1 to 3 get no value.
  </Step>
  <Step title="First window: 70, 72, 70, 72">
    Mean $= (70 + 72 + 70 + 72) / 4 = 284 / 4 = 71$. Every reading is 1 away from 71, so $s = \sqrt{(1 + 1 + 1 + 1)/4} = 1$.
  </Step>
  <Step title="Last window: 90, 110, 90, 110">
    Mean $= 400 / 4 = 100$. Every reading is 10 away from 100, so $s = \sqrt{(100 + 100 + 100 + 100)/4} = 10$.
  </Step>
  <Step title="Read the features">
    Resting looks like $[71, 1]$ and exercising like $[100, 10]$. A classifier with just these two numbers per window can tell the activities apart.
  </Step>
</Steps>

In pandas, `rolling(k)` gives a window that **ends at the current row**, so the first $k-1$ rows are `NaN`. In a Final-round task without pandas, NumPy builds all the windows at once:

<Tabs>
<Tab label="pandas">

```python
import pandas as pd

hr = pd.Series([70, 72, 70, 72, 90, 110, 90, 110])
feats = pd.DataFrame({
    'hr': hr,
    'mean_4': hr.rolling(4).mean(),
    'std_4': hr.rolling(4).std(ddof=0).round(2),
})
print(feats)
```

`ddof=0` divides by $k$, as in our formula. Pandas' default (`ddof=1`) divides by $k - 1$, giving slightly bigger values such as 1.15 for the first window. `hr.rolling(4).skew()` and `.kurt()` give the next two moments (with small-sample corrections, and `.kurt()` subtracts 3 so that a bell curve scores 0).

</Tab>
<Tab label="NumPy">

```python
import numpy as np
from numpy.lib.stride_tricks import sliding_window_view

hr = np.array([70, 72, 70, 72, 90, 110, 90, 110])
w = sliding_window_view(hr, 4)
print(w.shape)               # one row per window
print(w.mean(axis=1))
print(w.std(axis=1).round(2))
```

```text
(5, 4)
[ 71.   76.   85.5  90.5 100. ]
[ 1.    8.12 16.15 13.44 10.  ]
```

`np.std` divides by $k$ by default, so these match the pandas column `std_4`.

</Tab>
</Tabs>

Eight readings and a window of 4 give $8 - 4 + 1 = 5$ windows. In general, $n$ readings give $n - k + 1$ full windows.

<Tip title="The same idea in image models">

**Pooling** in a convolutional network slides a small window (say 2×2 pixels) over an image and keeps one summary number per window: its maximum (max pooling) or its mean (average pooling).

</Tip>

<Mistake title="Windows that peek into the future">

A **centred** window (`rolling(k, center=True)`) or a feature such as "average of the next 3 days" uses readings from after the moment you are predicting. It looks brilliant in testing and is impossible in real use. When you predict the future, every window must end at, or before, the current time. This is a form of **leakage**, the topic of the next lesson, [Splitting data and avoiding leakage](#/learn/data-and-features/splitting-and-leakage).

</Mistake>

<Note title="Features a model learns for you: PCA and embeddings">

Hand-made features need knowledge; two methods learn features from the data instead. <Term def="Principal component analysis: an unsupervised method that finds new axes along which the data varies most, and keeps the top few as new features. Each new feature is a weighted sum of the original ones.">PCA</Term> compresses many correlated columns into a few new ones, each a weighted sum of the originals chosen to keep as much of the spread (variance) as possible, without looking at the labels: on scikit-learn's 8×8 digit images, 10 PCA features keep 74% of the variance of the 64 pixels. An <Term def="A short list of real numbers (a dense vector) that a neural network learns to represent a word, image or sound, so that similar things get nearby vectors.">embedding</Term> is a dense vector that a neural network learns for a word, an image or a sound, and a simple classifier on embeddings often beats hand-made features. You will study PCA in [Principal component analysis](#/learn/unsupervised-learning/pca), and embeddings when you work with text and images.

</Note>

<ExamTip>

How NOAI asks about this:

- "Data is not linearly separable" in a question points to one of three fixes: add features (such as $x^2$ or products), use a kernel, or use a non-linear model (trees, neural networks). Transforms like $2x$ or $x + 5$ never help a linear model.
- Know the column count: `PolynomialFeatures(degree=2)` on $p$ features gives $\frac{(p+1)(p+2)}{2} = \binom{p+2}{2}$ columns, which is 6 for $p = 2$ and 10 for $p = 3$ (one fewer without the bias).
- `rolling(k)` leaves $k - 1$ leading `NaN`s, and $n$ readings give $n - k + 1$ windows.
- PCA reduces dimensions and ignores labels; embeddings are dense vectors, unlike sparse one-hot vectors.

</ExamTip>

<Takeaways>

- A linear model draws straight boundaries in its features. A good new feature ($x^2$, $x_1^2 + x_2^2$, $x_1 x_2$) turns a curved problem into a straight one.
- Polynomial and interaction features are powers and products; `PolynomialFeatures` makes $\binom{p+d}{d}$ columns from $p$ features at degree $d$, so the count explodes, and more features can mean more overfitting.
- Domain features (ratios, differences, date parts, bins) encode what you know. Clock time belongs on a circle: $(\sin, \cos)$.
- Sliding windows turn long sequences into fixed-size vectors of rolling statistics (mean, standard deviation, min, max). Windows must not look into the future.
- PCA and learned embeddings are features too: compact summaries of high-dimensional data.

</Takeaways>
